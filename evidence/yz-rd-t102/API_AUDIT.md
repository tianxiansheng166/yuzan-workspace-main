## Confirmed gaps to fix

1. Remove fake/demo login, offline sessions, fixed token and fixed school fallback; use the existing auth API and the returned server identity. Keep the existing login presentation and show accessible retryable errors. **T093's fail-closed change is carried narrowly.**
2. Make Today surface course-list failures distinctly from a legitimate empty catalog. **Implemented in T102.**
3. Isolate optional recommendations/statistics failures from the required course-detail read; do not invent zero metrics. **Implemented in T102.**
4. Map published media fields from the server's nested `activity.content` when top-level aliases are absent; never introduce a fixed playback URL. **Implemented and adapter-tested.**
5. Replace Growth's baked example values with authorized API-backed data while retaining the original page's distinct visual hierarchy. An unavailable endpoint must yield an explicit unavailable state, not sample scores/comments. **Implemented in T102 source; live verification remains NOT_RUN.**
6. Implement and test T099 partial/all-blank submission without weakening auth, state transition, failed-upload, pending-save or idempotency protections. **Implemented and unit-tested in T102.**
7. Add regression coverage for dynamic route IDs and the failure/empty states above. **Fixture tests added.** Fixture tests remain `TEST_FIXTURE_ONLY`; they do not count as real API or browser acceptance.
8. Keep released student feedback backed by class-authorized and atomic teacher writes. **T095 is carried narrowly; PostgreSQL concurrency E2E remains NOT_RUN.**

## T102 source-level verification notes

- `SaveActivityAttemptDto.videoPosition` accepts values from 0 through 1, and
  `StudentCoursesService` stores that top-level fraction as activity progress.
  BASE `CoursePlayerState.saveActivityAttempt` replaced the media controller's
  fractional value with its 0–100 display percentage. T102 now forwards the
  validated fraction. A fixture regression checks assignment, submission,
  activity, expected revision, and persisted fraction; a live write was not run.
- The Growth adapter does not read `teacherFeedback` from an AssessmentReport; that field is absent from `toAssessmentReportResponse`. It reads released comments from `getAssessmentHistoryEvents(enrollmentId)` instead.
- T095's feedback write now checks the submission's active student enrollment and teacher class assignment, then atomically compare-and-swaps the `NEEDS_REVIEW` submission before creating its released Feedback row. Invalid/stale writes create no feedback entry.
- Source-level API mapping and fixture tests do not prove live authorization, media delivery, or browser behavior. Those E2E checks remain `NOT_RUN`.
