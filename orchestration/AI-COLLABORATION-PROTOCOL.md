# AI 协作协议

## 不可违反

1. 不直接在 `main` 工作。
2. 不修改任务白名单外的文件。
3. 不绕过 OpenAPI 自创请求/响应。
4. 不绕过 Prisma 自创表或字段。
5. 不通过前端硬编码假数据“完成”业务。
6. 不删除或重置其他代理的未提交工作。
7. 不运行不可逆数据命令，除非任务明确批准。
8. 不提交密钥、真实学生数据或外部版权不明资产。
9. 不将自动 AI 结果伪装为人工最终结论。
10. 不宣称测试通过，除非实际运行并记录命令和输出。

## 开始前必须回答

- 此任务服务哪个用户和哪条旅程？
- 上游契约和依赖是什么？
- 数据由谁创建、存在哪里、谁能访问？
- 失败/离线/权限不足时页面和 API 怎么表现？
- 哪些共享文件可能需要变化？
- 完成如何自动验证？

## 实现过程

- 小提交，每个提交只表达一项意图；
- 先测试核心规则，再接 UI；
- 保留 request ID 和可观察错误；
- 业务权限放服务层；
- 使用契约生成类型；
- 视觉代码不创建新的全局覆盖补丁；
- 公共抽象只有出现两处稳定复用后再提取。

## 停止条件

遇到以下情况立即停止并提交问题：

- 任务规则与 OpenAPI/Prisma 冲突；
- 需要新枚举/状态/错误码；
- 需要修改别人的 allowed path；
- 发现敏感数据或安全漏洞；
- 产品规则存在两种合理解释；
- 设计资产可能文化不准确或版权不明；
- 依赖任务的 mock 与真实实现不兼容。

## 交付要求

- 用户故事和实现摘要；
- 修改文件；
- schema/contract 影响；
- 测试命令与结果；
- 截图/录屏；
- 权限和异常测试；
- 迁移和回滚；
- 已知限制；
- 下一任务建议。
