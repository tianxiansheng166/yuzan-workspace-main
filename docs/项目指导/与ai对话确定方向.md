# 与 AI 对话确定方向

> 来源：用户提供的 `pasted-text.txt`。  
> 本文件按主题整理口语转写，保留原始产品意图；它是方向讨论记录，不直接作为开发完成事实。完整原文仍以用户提供的附件为准。

## 一、用户提出的核心问题

当前平台没有达到应有的功能性，亮点不突出。项目最初是为了服务西藏地区学生学习国家通用语言文字，但现在学生端、教师端、志愿者端和管理端虽然有很多页面，功能却没有形成一套完整、顺畅、可持续使用的系统。

真正需要重新明确的是：

- 平台最核心的产品亮点是什么；
- 学生为什么要持续使用；
- 教师为什么愿意使用；
- 课程、练习、测评、录音、报告和教学干预如何连成一条闭环；
- 每个角色到底应该得到什么；
- 如何停止“很多、很杂、很乱”的模块扩张，形成一份总章程后快速推进。

## 二、学生端应形成的两大核心能力

### 1. 课程不是单纯看内容

学生应当能通过网页自主学习课程。课程完成后必须有口语练习和书面练习，帮助学生提高国通语实际使用能力。

课程相对于普通网课的差异应是：

```text
课程学习
→ 听辨与示范
→ 口语练习
→ 书面练习
→ 数据分析
→ 学习报告
→ 下一步改进建议
```

课程的护城河不是视频或文章数量，而是学完后能继续练习、产生证据、得到分析并进入下一步。

### 2. 语音练习与测评

语音评测能力应参考成熟听说系统的完整执行逻辑，把适合的能力转化为国通语学习与测评场景。

当前测评中心像一套固定的一次性流程：

- 不知道练习从哪里来；
- 无法选择和更换练习题；
- 口语环节不能按题型拆分；
- 听什么、说什么不能配置；
- 每套练习没有独立评分标准；
- 学校不发布测验时，学生缺少自主练习入口；
- 完成后的数据没有进入长期分析。

正确方向是把测验中间的执行过程做成通用页面。学生选择任意练习后：

```text
查看练习信息
→ 开始练习
→ 检查麦克风、扬声器和网络
→ 倒计时
→ 听示范或听材料
→ 跟读、朗读、复述或回答
→ 上传录音
→ 完成书面练习
→ 提交
→ 后台按该练习的答案和评分标准处理
→ 生成报告
```

平台中应该有很多套可复用练习。学生可以自主练，教师也可以把口语题和书面题组成练习、作业或统一测验后发给学生。

## 三、学生数据不能只生成一次分数

学生做完所有练习后，后台应当分析：

- 哪部分不足；
- 哪部分已经改善；
- 哪个能力长期不稳定；
- 下一步应该练什么；
- 哪种练习对学生有效；
- 是否需要教师进行个性化指导。

报告应基于录音、答案、题目、评分标准和教师反馈，而不是只给一个总分。

## 四、教师端应提供的核心价值

### 1. 班级和学生数据分析

教师需要看到：

- 班级学习和练习进度；
- 每项练习完成情况；
- 班级共性问题；
- 单个学生的薄弱点；
- 近期变化；
- 需要教师复核的证据；
- 可以采取的教学行动。

教师应能依据这些数据：

- 给学生个性化指导；
- 布置针对性练习；
- 调整课堂教学策略；
- 将共性问题加入下一次课堂。

### 2. 无障碍的智能备课

当前教师工具入口多、步骤多、卡片多，不能真正减负。

教师备课应当只有一个连续工作区，先选择：

- 教哪个班；
- 使用什么教材；
- 教什么主题；
- 希望解决什么问题；
- 需要哪些练习。

然后提供两种模式：

#### 一键生成

教师用自然语言说明需求，系统读取经授权的班级数据、教材和平台资源，生成可编辑的教学目标、课堂步骤、示范材料、练习和课后作业草稿。

#### 手动组装

教师从平台资源库选择教材解读、教案模板、示范材料、口语练习和书面练习，逐步组合成一套课件或教案。

无论哪种模式，AI 只能生成草稿，教师必须预览和确认。

### 3. 便捷布置练习

教师应能：

- 从练习库直接选择；
- 按课堂内容选择；
- 按班级共性问题选择；
- 为个别学生选择；
- 将口语和书面题组合；
- 预览后发布；
- 查看结果并追加巩固练习。

教师真正需要的流程是：

```text
选择目标
→ 选择学生
→ 选择或生成练习
→ 预览
→ 发布
```

## 五、志愿者端应提供的核心价值

志愿者端不应复制教师后台，重点是：

1. 培训与认证；
2. 学生与志愿者一对一帮扶；
3. 帮扶准备助手；
4. 帮扶记录和教师协同。

志愿者可描述本次帮扶目标，平台利用授权资料生成可编辑的目标、材料、步骤、口语练习、课后巩固和记录模板。

志愿者只能看到完成本次帮扶所需的最小数据，不能访问完整学生档案。

## 六、管理端定位

管理端不需要成为产品亮点，主要承担：

- 学校和班级总览；
- 教学质量趋势；
- 课程、练习和评分标准治理；
- 教师使用情况；
- 资源治理；
- 志愿者治理；
- 供应商和额度；
- 隐私和审计。

当前阶段不应优先扩张管理端页面。

## 七、AI 在原对话中给出的核心回应

AI 认为问题不是页面美化，而是产品能力没有围绕一个内核组织。当前课程、测评、录音、报告、教师工具和志愿者功能彼此分离，看起来都有，实际没有形成系统。

AI 提出的产品定位是：

> 面向西藏地区学生的国家通用语言文字学习、练习、评测和教学干预一体化平台。

核心公式是：

```text
课程内容
× 统一练习与测评引擎
× 普通话语音评测
× 长期能力画像
× 教师与志愿者智能干预
```

AI 强调三层护城河：

1. 国通语课程与练习体系；
2. 一套练习引擎、多种交付模式；
3. 长期能力数据与智能干预。

## 八、原对话提出的练习模型

### PracticeSet

一套可复用练习或试卷，包含名称、说明、年级、难度、时长、能力标签、section、评分方案、发布版本、来源和自主练习规则。

### PracticeSection

一套练习中的环节，例如：

```text
听辨
跟读
朗读
听后复述
书面练习
```

### PracticeItem

口语题型候选：

```text
LISTEN_ONLY
LISTEN_REPEAT
READ_ALOUD
LISTEN_RETELL
LISTEN_ANSWER
DIALOGUE_RESPONSE
FREE_SPEAKING
```

书面题型候选：

```text
SINGLE_CHOICE
MULTIPLE_CHOICE
FILL_BLANK
ORDERING
SHORT_ANSWER
WRITTEN_EXPRESSION
```

题目还应配置示范音频、是否显示文本、播放次数、准备时间、录音时间、重录次数、目标文本、参考答案、关键内容点、能力标签、最低音频质量和人工复核规则。

### ScoringRubric

不同题型使用不同评分标准，并保存：

```text
rubricVersion
scorerVersion
sectionWeight
itemWeight
passThreshold
reviewThreshold
```

## 九、原对话提出的角色收敛

### 学生端

```text
今日学习
课程学习
练习与测评
成长档案
```

### 教师端

```text
班级洞察
智能备课
练习与作业
复核与干预
```

### 志愿者端

```text
培训与认证
一对一帮扶工作台
帮扶准备助手
```

### 管理端

只做学校、内容、评分、资源、模型、隐私和审计治理。

## 十、原对话提出的第一条黄金闭环

```text
学生选择古诗文朗读与理解训练
→ 查看详情
→ 设备检查
→ 听示范音频
→ 跟读
→ 看文朗读
→ 听后复述
→ 完成书面理解题
→ 上传录音和答案
→ 自动评分
→ 教师复核低置信度部分
→ 生成报告
→ 更新能力画像
→ 推荐下一项练习
→ 教师看到结果
→ 教师布置巩固练习
```

这条链路跑通后，其他练习主要替换内容、题型、执行规则和评分标准。

## 十一、这份对话如何用于项目

原对话的正确用途是确定：

- 产品定位；
- 核心用户价值；
- 统一练习引擎方向；
- 角色边界；
- 第一条黄金闭环；
- P0/P1/P2 取舍。

它不能直接证明：

- 练习模型已经实现；
- 测评 API 已经完整；
- worker 已经可用；
- 语音评分有效；
- 前端已经没有静态数据；
- 测试已经通过。
