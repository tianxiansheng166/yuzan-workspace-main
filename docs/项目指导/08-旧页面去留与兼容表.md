## 0. 总体策略

### 0.1 三条原则

1. **数据先行**：旧路由中硬编码的 demo ID（`SZ20250530-PT-0032` / `RD250530-010` / `WR250530-001` / `spring-2` / `submission-1`）必须替换为 FX 中的真实 ID（`ATT-20260720-001` / `REC-20260720-0001..0005` / `RVW-20260720-0001..0002`），否则一律退役。
2. **兼容跳转优先**：旧路由不立即删除，而是用 307 临时重定向或应用层解析跳转到新路由，保留 6 个月的兼容窗口（至 2027-01-20），期间在日志中统计访问量，新流程稳定且旧访问量归零后再决定永久跳转或退役。
3. **不破坏教师端**：教师端 `web-runtime/teacher/**` 的页面不在此 5 条路由范围内，但若教师端引用了旧 demo ID（如 `/teacher/reviews/submission-1/`），需同步替换。

### 0.2 处理方式枚举

| 处理方式 | 含义 | 适用条件 |
| --- | --- | --- |
| **保留改造** | 路由路径不变，但内部实现完全替换为基于 FX 的新组件 | 旧路由与新页面 1:1 对应 |
| **合并** | 多条旧路由合并为一条新路由 | 旧路由按题型拆分，新路由统一执行器 |
| **兼容跳转** | 旧路由保留 6 个月，访问时 307 跳转到新路由 | 旧路由与新路由路径不同 |
| **退役** | 旧路由直接删除，不提供跳转 | 旧路由无实际用途或已被完全替代 |
| **新建** | 新路由，无旧路由对应 | 新页面在旧版本中不存在 |

## 2. 详细处理方案

### 2.1 路由 1：`/assessment` → 合并为 P-PR-03 + P-EX-04

**现状**：
- 文件：`web-runtime/assessment/_shell.html`（749 字节）+ `index.html`（897 字节），都是壳，加载 `/assessment/assets/app.js`（91KB SPA）。
- `route-manifest.json`：版本 4.0.0-prototype，`coreObject=AssessmentSession`，固定 `sessionId=SZ20250530-PT-0032`，9 条子路由。
- `README.md`：9 个核心页面 + 1 个书面支撑页，状态机包含 `LOADING_ITEM/PLAYING_PROMPT/PREPARING/RECORDING/PAUSED/REVIEWING/UPLOADING/UPLOAD_FAILED/UPLOADED/PROCESSING/REJECTED_AUDIO/READY`。

**问题**：
1. SPA 内嵌状态机与 [05-P0黄金闭环产品规格.md](./05-P0黄金闭环产品规格.md) §7 的 Attempt 状态机不一致（多了 `PAUSED`、`REJECTED_AUDIO` 等中间态）。
2. 固定 `sessionId=SZ20250530-PT-0032`，无法承载多学生多练习。
3. 91KB SPA 难以增量改造为统一练习引擎架构。

**处理**：
- 拆分为多个新页面：
  - 练习与测评中心 → P-PC-01（`/student/practices`）
  - 准备与设备检查 → P-PR-03（`/student/practices/{practiceDefinitionId}/start`）
  - 通用执行器（执行入口）→ P-EX-04（`/student/practices/run/{attemptId}`，只负责解析当前 Item 并跳转）
  - 通用执行器（具体 Item）→ P-EX-04（`/student/practices/attempts/{attemptId}/items/{itemAttemptId}`，渲染答题 UI）
- 旧 SPA 的状态机映射到新 Attempt 状态机（见 §3 状态映射表）。
- 旧 SPA 的 9 个子页面映射到新 9 页面地图（见 [06-P0页面地图与状态流.md](./06-P0页面地图与状态流.md) §12）。

**数据迁移**：
- `SZ20250530-PT-0032` → `ATT-20260720-001`（来自 `FX.attempt.attemptId`）
- `coreObject=AssessmentSession` → `coreObject=Attempt`（命名空间迁移）
- `route-manifest.json` 的 9 条子路由 → FX.pageStoryArc 的 9 个 pageId

**兼容跳转**：
- `/assessment` → 应用层解析 → `/student/practices`（P-PC-01，进入新练习中心）
- `/assessment?sessionId={oldId}` → 应用层解析 → 先查找当前未完成 Attempt，有则跳 `/student/practices/run/{attemptId}`，无则跳 `/student/practices`
- 6 个月后（2027-01-20）删除 `/assessment` 路由

**导航影响**：
- 顶部导航栏「测评」Tab 改名为「练习」，指向 `/student/practices`。
- 教师端 `web-runtime/teacher/assessments/**` 保持不变（教师端不在本次合并范围）。

### 2.2 路由 2：`/assessment/reading/2` → 合并为 P-EX-04

**现状**：
- SPA 内朗读子路由，固定 `readingId=RD250530-010`、路径参数 `spring-2`（指向《春晓》或某固定篇目）。
- 单独的朗读页面，与书面理解页 `/assessment/written` 分离。

**问题**：
1. 按题型拆分页面，与黄金闭环的「统一执行器」理念冲突 —— P-EX-04 应承载所有 5 种 Section 类型。
2. `spring-2` 是硬编码篇目标识，无法承载多版本多题目。
3. 朗读页与跟读、复述页共享大量 UI（录音按钮、波形图、重录按钮），拆分导致重复代码。

**处理**：
- 合并到 P-EX-04（`/student/practices/run/{attemptId}`）。
- P-EX-04 根据 `itemType`（`LISTEN_ONLY / LISTEN_REPEAT / READ_ALOUD / LISTEN_RETELL / SINGLE_CHOICE / MULTIPLE_CHOICE / SHORT_ANSWER`）动态渲染不同 UI，但共享同一执行器框架。

**数据迁移**：
- `RD250530-010` → `IA-RA-001`（朗读《登鹳雀楼》）或 `IA-RA-002`（朗读《望庐山瀑布》），由 `attemptId` 下的 `itemAttempts` 决定。
- `spring-2` → `ITM-RA-001` / `ITM-RA-002`（itemRefId）。

**兼容跳转**：
- `/assessment/reading/2` → 307 → 先解析当前未完成 Attempt，有则跳 `/student/practices/run/{attemptId}`，无则跳 `/student/practices`（练习中心）
- `/assessment/reading/{n}` → 307 → `/student/practices/run/{attemptId}`（n 无法映射时跳到练习中心）
- 6 个月后删除。

**导航影响**：无（该路由不出现在顶部导航，只在 SPA 内部跳转）。

## 3. 状态机映射表

> 旧 SPA 状态机（来自 `web-runtime/assessment/README.md`）→ 新 Attempt 状态机（来自 [05-P0黄金闭环产品规格.md](./05-P0黄金闭环产品规格.md) §7）。

| 旧 SPA 状态 | 新 Attempt 状态 | 说明 |
| --- | --- | --- |
| `LOADING_ITEM` | `IN_PROGRESS`（ItemAttempt: `PRESENTED`） | 旧状态细分到 Item 级别，新状态机在 Attempt 与 ItemAttempt 两层 |
| `PLAYING_PROMPT` | `IN_PROGRESS`（ItemAttempt: `ANSWERING`） | 播放示范音频属于答题中 |
| `PREPARING` | `IN_PROGRESS`（ItemAttempt: `ANSWERING`） | 准备倒计时属于答题中 |
| `RECORDING` | `IN_PROGRESS`（ItemAttempt: `ANSWERING`） | 录音中属于答题中 |
| `PAUSED` | **移除** | 新状态机不支持暂停（`pauseBtn` 已在 detail/app.js 中禁用） |
| `REVIEWING` | `READY_TO_SUBMIT` | 提交前检查 |
| `UPLOADING` | `SUBMITTED` → `PROCESSING`（ItemAttempt: `SYNCED`） | 上传属于提交后处理 |
| `UPLOAD_FAILED` | `IN_PROGRESS`（ItemAttempt: `SAVED_LOCAL`） | 失败回退到本地保存，可重试 |
| `UPLOADED` | `PROCESSING`（ItemAttempt: `SYNCED`） | 上传完成等待评分 |
| `PROCESSING` | `PROCESSING` | 评分中 |
| `REJECTED_AUDIO` | `IN_PROGRESS`（ItemAttempt: `ANSWERING`，错误码 `AUDIO_QUALITY_REJECTED`） | 不消耗重录配额，强制重录 |
| `READY` | `COMPLETED` | 报告就绪 |

**新状态机额外状态**（旧 SPA 无对应）：
- `CREATED`：Attempt 创建后、设备检查前。
- `DEVICE_CHECK`：设备检查中。
- `NEEDS_REVIEW`：评分完成但有 Item 需教师复核。
- `FAILED`：评分失败或内容哈希不匹配。
