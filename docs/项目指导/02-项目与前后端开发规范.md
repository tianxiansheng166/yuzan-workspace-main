# 项目与前后端开发规范

> 本规范服务于当前赶工阶段。目标是让开发更快形成真实闭环，不是增加形式工作。

## 1. 事实源与决策规则

### 1.1 当前收敛期

在 OpenAPI 尚未补齐前，判断事实使用：

1. 当前可运行代码和真实接口响应；
2. Prisma schema 与迁移；
3. 实际测试结果；
4. OpenAPI；
5. 状态文档和历史说明。

### 1.2 契约冻结后

赶工第一个门槛完成后，顺序改为：

1. OpenAPI 和版本化领域契约；
2. Prisma schema 与迁移；
3. 后端实现；
4. 前端生成类型或 API 适配；
5. 文档与测试。

后端 Controller、前端 `api-client.js` 和 OpenAPI 不允许继续分别演进。

## 2. 目录职责

| 目录 | 职责 |
|---|---|
| `apps/api` | HTTP API、认证、租户、领域编排和持久化 |
| `apps/worker` | 耗时异步任务，不直接承载用户同步请求 |
| `infra/database/prisma` | 数据模型与迁移事实 |
| `packages/contracts/openapi` | 前后端 HTTP 契约事实 |
| `web-runtime` | 当前用户前端和 API 代理 |
| `docs/项目指导` | 当前产品方向、规范、阶段计划和验收 |

`apps/apps-web` 不进入当前开发范围。

## 3. 统一命名

业务对象使用以下术语：

- `PracticeDefinition`：练习稳定身份；
- `PracticeVersion`：不可变发布版本；
- `PracticeSection`：练习环节；
- `PracticeItem`：练习题目引用与执行配置；
- `ScoringRubricVersion`：评分量表版本；
- `PracticeDelivery`：把练习交付给谁、何时、以什么规则执行；
- `Attempt`：学生的一次执行；
- `Evidence`：录音、答案、设备检查和处理结果；
- `Review`：教师对机器结果的确认或修改；
- `Report`：单次结果；
- `LearnerProfile`：长期能力画像；
- `Intervention`：经教师确认的干预行动。

前端文案可用“练习”“作业”“阶段测评”，后端内部不得为每个叫法复制一套模型。

## 4. API 规范

### 4.1 路径和版本

- 公共 API 固定前缀 `/api/v1`；
- 资源使用复数名词；
- 路径只表达资源层级，不表达按钮文案；
- 动态对象必须使用真实 ID；
- 不再新增 `demo`、`spring-2`、`submission-1` 这类业务 ID；
- 兼容旧路由时使用明确适配层和退役日期。

### 4.2 响应

成功响应保持统一包装：

```json
{
  "data": {},
  "meta": {
    "requestId": "..."
  }
}
```

列表返回：

```json
{
  "data": {
    "items": [],
    "nextCursor": null
  },
  "meta": {
    "requestId": "..."
  }
}
```

错误返回：

```json
{
  "error": {
    "code": "PRACTICE_VERSION_NOT_FOUND",
    "message": "练习版本不存在或不可访问",
    "details": {}
  },
  "meta": {
    "requestId": "..."
  }
}
```

前端只根据稳定 `code` 分支，不根据中文 message 猜业务状态。

### 4.3 错误分类

至少区分：

- `UNAUTHENTICATED`：未登录或会话过期；
- `FORBIDDEN_TENANT`：学校范围错误；
- `FORBIDDEN_RESOURCE`：资源不属于当前用户；
- `NOT_FOUND`：不存在或用不可枚举语义隐藏；
- `VALIDATION_FAILED`：输入不合法；
- `CONFLICT`：状态冲突或版本冲突；
- `IDEMPOTENCY_CONFLICT`：相同键不同请求；
- `PROVIDER_NOT_CONFIGURED`：供应商未配置；
- `PROVIDER_UNAVAILABLE`：供应商已配置但不可用；
- `PROCESSING_PENDING`：异步处理中；
- `AUDIO_QUALITY_REJECTED`：音频不满足最低要求。

### 4.4 幂等和并发

以下写入必须支持幂等：

- 创建 attempt；
- 保存书面答案；
- 完成录音；
- 提交 attempt；
- worker 回写结果；
- 教师发布复核；
- 离线 outbox 重放。

规则：

- 客户端为一次业务动作生成稳定 `idempotencyKey`；
- 同一 key、相同 payload 返回原结果；
- 同一 key、不同 payload 返回 `IDEMPOTENCY_CONFLICT`；
- 更新使用 `revision` 或 `expectedUpdatedAt`；
- 前端冲突时显示“数据已在其他位置更新”，不自动覆盖。

### 4.5 OpenAPI 门槛

每个新增端点必须同时具备：

- path、method、权限和学校范围；
- request/response schema；
- 所有业务错误；
- 正常示例；
- 空、权限不足、冲突和供应商不可用示例；
- 前端消费方；
- 契约测试。

## 5. 数据库规范

### 5.1 租户和资源范围

- 学校数据表必须带 `schoolId`；
- 查询不能先按裸 `id` 获取后再检查学校；
- 优先使用复合唯一键或 `schoolId + id` 查询；
- 学生资源必须继续校验 `enrollmentId/userId`；
- 教师访问必须校验任课班级或明确管理员角色；
- worker 回写必须通过内部认证，且校验 job、recording、item 的关联关系。

### 5.2 发布版本不可变

课程、练习和评分量表使用：

```text
DRAFT → IN_REVIEW → PUBLISHED → RETIRED
```

- `PUBLISHED` 不原地修改；
- 修改时创建下一版本；
- attempt 保存版本和规则快照；
- 历史报告永远用当时的内容与量表解释。

### 5.3 JSON 使用边界

JSON 可以保存：

- 版本化 prompt 快照；
- 供应商原始结果；
- 可审计的规则快照；
- 尚未稳定到独立列的低频元数据。

JSON 不可以替代：

- 学校、用户、班级、练习、版本、交付和 attempt 关系；
- 需要索引和权限过滤的字段；
- 核心状态机；
- 评分总分和关键维度；
- 长期统计口径。

### 5.4 迁移

迁移采用：

1. 增量加表或加可空列；
2. 写入新字段；
3. 回填和校验；
4. 切换读取；
5. 观察；
6. 最后再删除旧结构。

每次迁移必须说明：

- 数据量和锁风险；
- 回填方式；
- 回滚方式；
- 旧前端兼容时间；
- 是否影响 worker；
- 是否需要重新生成 Prisma client。

## 6. 后端模块规范

每个核心模块保持：

```text
controller
service
policy
dto
domain
ports
infra
module
```

职责：

- Controller：参数解析、身份上下文和响应；
- Service：用例编排和事务边界；
- Policy：角色、学校和资源权限；
- Domain：状态机、类型和业务错误；
- Port：存储或外部服务抽象；
- Infra：Prisma、S3、Redis、供应商适配。

禁止：

- Controller 直接写 Prisma；
- 用通用 `Error` 表达可预期业务错误；
- 只在前端隐藏按钮，不在服务端校验；
- 为页面临时返回硬编码业务数据；
- 用单个巨型 `stub.controller.ts` 持续扩展正式功能。

## 7. worker 规范

### 7.1 任务消息

消息至少带：

- `jobId`；
- `schoolId`；
- 关联资源 ID；
- 输入对象版本；
- 供应商和 scorer 版本；
- 幂等键；
- 尝试次数；
- trace/request ID。

消息不携带完整敏感数据或长期有效下载地址。

### 7.2 状态机

建议统一为：

```text
CREATED
→ QUEUED
→ PROCESSING
→ AUTO_RESULT | NEEDS_REVIEW | REJECTED_AUDIO
→ FINALIZED
```

失败保留：

```text
FAILED_RETRYABLE
FAILED_FINAL
PROVIDER_NOT_CONFIGURED
```

不得由前端定时器假装任务完成。

### 7.3 重试和回写

- 只有可恢复错误自动重试；
- 4xx 配置或输入错误不盲目重试；
- worker 回写是幂等更新；
- 重复任务不能产生多份最终分数；
- 所有终态有时间、版本和错误码；
- 对象存储、评分服务和 API 回写分别记录耗时。

### 7.4 测试最低线

worker 至少测试：

- 正常评分；
- 对象不存在；
- 音频质量拒绝；
- 供应商超时；
- 供应商 4xx/5xx；
- 回写失败；
- 重复消费；
- 达到最大重试；
- 内部 key 缺失或错误；
- 不同学校资源交叉回写被拒绝。

## 8. 前端 `web-runtime` 规范

### 8.1 当前阶段技术决定

未来 20 个工作日保留现有多页运行时，不进行框架迁移。所有新增核心能力必须：

- 复用 `assets/api-client.js`；
- 使用动态路由参数；
- 将业务数据从 HTML 常量迁到 API 响应；
- 使用统一页面状态；
- 将演示模式限制为显式 `?demo=1`；
- 演示模式始终显示醒目标识，不写后端。

### 8.2 页面控制器

每个核心页面脚本按以下顺序：

```text
parseRoute()
→ requireSession()
→ loadData()
→ renderState()
→ bindActions()
→ submitAction()
→ refreshFromServer()
```

禁止一个脚本同时维护大量静态业务数据、DOM 模板、API 调用和路由映射而无边界。

### 8.3 状态模型

每个页面必须显式支持：

| 状态 | 要求 |
|---|---|
| `loading` | 可感知加载，不可重复提交 |
| `normal` | 展示真实数据 |
| `empty` | 说明为什么为空和下一步 |
| `error` | 展示稳定错误语义和重试 |
| `offline` | 说明哪些操作可本地保存 |
| `permission` | 不暴露资源是否存在 |
| `processing` | 显示真实服务端状态 |
| `provider-unavailable` | 不伪造 AI/评分结果 |

API 失败时不得继续展示旧硬编码数字并只弹一个 toast。

### 8.4 数据来源

允许：

- API 返回；
- 当前用户和学校会话；
- IndexedDB 中明确标注的离线草稿；
- 显式 demo 模式的数据。

禁止：

- 默认模式下的学生姓名、分数、班级人数和完成率常量；
- 以 `|| 42`、`|| 示例课程` 补出“完整页面”；
- 无真实 session 时跳到固定 session；
- 请求失败后静默吞错；
- 把 assignment ID 当 submission ID 或其他类型 ID。

### 8.5 录音

- 获取权限前说明用途；
- 录制状态与上传状态分离；
- Blob 只在需要时保存在 IndexedDB；
- 上传成功由后端确认；
- 断网时显示 `LOCAL_ONLY`；
- 恢复网络后由 outbox 重试；
- 用户可删除未上传录音；
- 页面离开前提示未保存状态；
- 不在日志中输出音频内容或下载 URL。

### 8.6 可访问性和响应式

- 控件使用真实 button/input；
- 所有图标有名称或 `aria-hidden`；
- 键盘可完成主流程；
- 焦点状态可见；
- 错误与状态使用文字，不只靠颜色；
- 390 像素下不能依赖缩放固定画布；
- 1440、1024、390 分别检查布局和交互；
- `prefers-reduced-motion` 下不阻碍操作。

## 9. 测试规范

### 9.1 测试分层

| 层级 | 重点 |
|---|---|
| Domain unit | 状态机、评分、权重、幂等 |
| Service unit | 权限、编排、异常 |
| Repository integration | Prisma、事务、租户 |
| Contract | OpenAPI 与 Controller/客户端一致 |
| Worker | 队列、重试、回写 |
| Frontend interaction | 状态和真实操作 |
| E2E | 教师发布到学生报告 |
| Security negative | 跨学校、跨班级、跨学生 |
| Visual | 1440、1024、390 |

### 9.2 数据库测试

- 数据库测试使用独立测试库；
- 没有测试库时明确跳过并输出原因；
- 不用无效凭据产生大批噪声失败；
- 每个测试隔离数据；
- 测试结束清理当前测试创建的数据；
- 不连接开发或生产数据库。

### 9.3 赶工门槛

每个检查点不要求全仓库全绿，但必须：

- 与本次改动相关的测试全绿；
- 原有失败数量不增加；
- 报告完整命令和结果；
- 明确环境失败与代码失败；
- P0 合并窗口前跑核心纵向 E2E。

## 10. 安全与隐私

- access token 不应长期停留在可被任意脚本读取的 localStorage；当前实现可作为过渡，正式上线前迁移到安全 cookie/session 策略；
- 所有读写在服务端执行学校和资源范围校验；
- 内部 worker API 必须 fail closed；
- 录音下载 URL 短时有效；
- 日志不写 token、密钥、录音 URL、真实学生数据；
- 供应商输入使用最小化字段；
- 教师导出、复核和修改结果写审计日志；
- 学生数据删除和保留策略覆盖对象存储、队列结果和缓存。

## 11. 完成定义

一个功能只有同时满足以下条件才算完成：

1. 用户动作清楚；
2. 数据来源真实；
3. API、DTO、OpenAPI 和客户端一致；
4. 数据库迁移和回滚已说明；
5. 服务端权限与租户负向测试通过；
6. 正常、加载、空、错误、离线和权限状态已处理；
7. 相关单元、集成或 E2E 测试实际运行；
8. 1440、1024、390 截图完成；
9. 无默认硬编码业务数据；
10. AI 输出可审阅、可追溯；
11. 已知限制写清；
12. 下一步入口明确。

## 12. 明确禁止

- 为了“看起来完整”返回假成功；
- 默认模式使用静态学生数据；
- 只做前端按钮，不做服务端规则；
- 只做后端接口，不接真实用户动作；
- 同一事实同时维护在多个 JSON 或脚本常量中；
- 把 OpenAPI 留到最后补；
- 未跑测试却写“测试通过”；
- 把 0 个测试文件的退出码 0 写成“worker 测试通过”；
- 用未经登记的生成图片或版权不明材料做课程内容；
- 用 AI 分数直接替代教师最终判断。
