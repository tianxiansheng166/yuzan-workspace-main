## D01 · humanReviewThreshold 固定

### 决策

- 古诗文 v1 的 `humanReviewThreshold` 固定为 **75**。
- 该字段属于 `ScoringRubricVersion`，不属于 `PracticeDefinition` 或 `PracticeVersion`。
- 未来其他 RubricVersion 可设定不同阈值（如低年级 70、高年级 80）。
- **P0 不按年级 / 学科自动调整**。

### 原因

- P0 只有一个 RubricVersion（`SRB-GSW-V1`），无需动态计算。
- 按年级自动变化需要额外的年级-阈值映射配置与教师覆盖机制，P0 复杂度不允许。

### 影响页面

- `P-RP-07`（正式报告）：`humanReviewThreshold=75` 用于「需要关注」标记与趋势图水平虚线。
- `P-HS-09`（历史记录）：趋势折线图标注 75 水平虚线。

### 影响契约

- `ScoringRubricVersion.humanReviewThreshold: number`（P0 固定 75，P1 可配置）
- `GET /api/v1/practice-versions/{id}` 响应含 `rubricVersion.humanReviewThreshold`

### 后续可扩展项

- P1：教师可在创建 RubricVersion 时设定自定义阈值。
- P1：按年级段提供默认阈值推荐值（G4-G6: 70, G7-G9: 75, G10-G12: 80）。

## D02 · SELF_PRACTICE 重录配额

### 决策

- `SELF_PRACTICE` 模式下 `reRecordPolicy.oralMaxExtra = 3`（在 Section 级 `reRecordLimit` 基础上额外允许 3 次重录）。
- 该值由 `PracticeDelivery.reRecordPolicy` 配置，非硬编码。
- **P0 不按难度自动推算**。

### 原因

- 按难度推算需要 `difficulty → oralMaxExtra` 映射规则与教师覆盖 UI，P0 不实现。
- 固定 3 次作为默认值足够宽松，适合绝大多数自主练习场景。

### 影响页面

- `P-EX-04`（通用执行器）：重录按钮在达到 `reRecordLimit + oralMaxExtra` 后禁用。

### 影响契约

- `PracticeDelivery.reRecordPolicy.oralMaxExtra: number`（P0 默认 SELF_PRACTICE=3, ASSIGNMENT=0）

### 后续可扩展项

- P1：`difficulty=EASY → 5, INTERMEDIATE → 3, ADVANCED → 1` 自动推算，教师可覆盖。

## D03 · STUDENT_APPEAL 延后

### 决策

- **P0 不展示学生申诉入口**。
- `reviewTrigger = STUDENT_APPEAL` 在领域模型和状态机中保留。
- 申诉功能进入 **P1**。

### 原因

- 申诉流程需要：学生提交申诉理由 → 教师接收通知 → 教师重新复核 → 结果通知学生。完整流程涉及通知系统与申诉队列，P0 不实现。
- 保留领域扩展点避免 P1 需要重新设计状态机。

### 影响页面

- `P-RP-07`（正式报告）：移除「申请复核」按钮。

### 影响契约

- `reviewTriggers` 枚举保留 `STUDENT_APPEAL`。
- `POST /api/v1/reviews` 的 `trigger` 字段允许 `STUDENT_APPEAL`（P1 启用）。

### 后续可扩展项

- P1：在 P-RP-07 增加「申请复核」按钮，触发 `STUDENT_APPEAL`。
- P1：教师复核工作台增加「申诉待处理」筛选。

## D04 · 巩固建议需教师确认

### 决策

- `consolidationSuggestion.automaticallyAddedToLearningPlan = false`。
- 教师确认后才写入 `LearningPlan`。

### 原因

- 自动加入学习计划可能在学生已有较多待办时造成负担，需教师根据学生整体情况判断。
- FX 中 `teacherConfirmed=true, confirmedBy=USR-TCH-2026-001` 已体现此流程。

### 影响页面

- `P-RP-07`（正式报告）：巩固建议卡片展示「加入学习计划」按钮（需教师操作），非自动加入。
- 教师端：巩固建议需教师点击确认后才生效。

### 影响契约

- `consolidationSuggestion.automaticallyAddedToLearningPlan: boolean`（P0 固定 false）
- `consolidationSuggestion.teacherConfirmed: boolean`
- `POST /api/v1/learning-plan/items` 需教师身份授权

### 后续可扩展项

- P1：对于 `SELF_PRACTICE` 模式，允许 `automaticallyAddedToLearningPlan=true`（学生自主练习无需教师确认）。
- P1：教师可设定全局策略「自动加入 / 需确认」。

## D05 · fixture Review 完整性

### 决策

- 为 `ITM-LR-001`（跟读《静夜思》，`status=REVIEWED`）补充完整 Review 记录 `RVW-20260720-0000`。
- 触发器：`TEACHER_DISCRETION`（教师主动复核）。
- 决策：`ACCEPT`（确认机器评分，分数不变 78.6）。
- 同时在 `IA-LR-001` 的 `itemAttempt` 中补充 `reviewedResult` 字段。
- 在 `FX.report.teacherFeedback.linkedReviewIds` 中加入 `RVW-20260720-0000`。
- 在 `FX.scoringRubric.reviewTriggers` 中新增 `TEACHER_DISCRETION` 触发器。

### 原因

- 数据完整性要求：所有 `status=REVIEWED` 的 ItemAttempt 必须在 `reviews` 数组中有对应证据记录，否则报告页无法展示复核详情。
- `TEACHER_DISCRETION` 触发器覆盖教师主动复核场景（置信度 ≥ 0.70 但教师仍选择复核）。

### 影响页面

- 所有引用 `FX.reviews` 的页面（P-RP-07、教师复核页）。
- FX 数据完整性校验。

### 影响契约

- `reviews` 数组从 2 条增至 3 条。
- `reviewTriggers` 枚举新增 `TEACHER_DISCRETION`。
- `itemAttempt.reviewedResult` 对 IA-LR-001 从无到有。

### 后续可扩展项

- 无（一次性数据修正，已完成）。

## D06 · 禁止 submission-1 路由

### 决策

- **禁止使用 `submission-1` 原型路径**作为教师复核路由。
- 使用真实 `reviewId` 或 `attemptId` 作为路由参数。
- fixture、页面地图（06）、兼容表（08）保持一致。

### 原因

- `submission-1` 是 web-runtime 原型阶段的硬编码标识，无法承载多学生多 Attempt 的复核场景。
- 使用真实 ID 使路由可被直接解析，无需维护额外的映射表。

### 影响页面

- 教师复核页：路由从 `/teacher/reviews/submission-1/` 改为 `/teacher/reviews/{reviewId}` 或 `/teacher/reviews/{attemptId}`。
- `P-RP-07`（正式报告）：教师端路由同步修改。

### 影响契约

- `GET /api/v1/reviews/{reviewId}` 或 `GET /api/v1/attempts/{attemptId}/reviews`
- 教师端 `navRoutes.review` 从固定路径改为动态路径

### 后续可扩展项

- P1：复核页支持批量复核（同一 Attempt 下多个 Item），路由可简化为 `/teacher/reviews?attemptId={attemptId}`。

## D07 · MODE_NOT_SUPPORTED 双态

### 决策

- `MODE_NOT_SUPPORTED`（`COURSE_PRACTICE` / `STAGE_ASSESSMENT`）的 UI 行为：
  - **学生端**：隐藏入口（不展示卡片或 Tab）。
  - **教师配置端**：显示禁用态（灰色 + tooltip 说明「该模式暂未开放」）。

### 原因

- 学生端展示禁用态可能引起困惑（「为什么有但不能点？」），隐藏更干净。
- 教师端需要知道哪些模式存在但未开放，以便规划未来课程配置。

### 影响页面

- `P-PC-01`（练习与测评中心）：不展示 `COURSE_PRACTICE` / `STAGE_ASSESSMENT` 入口。
- 教师配置页：展示禁用态。

### 影响契约

- `MODE_NOT_SUPPORTED` 错误码 UI 行为分为 `student: hidden` / `teacher: disabled_with_reason`

### 后续可扩展项

- P1：`COURSE_PRACTICE` 开放后从隐藏变为可点击。
- P2：`STAGE_ASSESSMENT` 开放。

## D08 · 网络检测非阻塞

### 决策

- **网络检测失败不阻止开始练习**。
- 网络失败时显示 `LOCAL_ONLY` 标记，提示学生录音将保存在本地。
- **最终提交前必须全部录音同步完成**（不可在离线状态下提交）。
- **麦克风、扬声器和浏览器录音能力失败属于阻塞**（不可开始练习）。

### 原因

- 西藏地区网络不稳定，强制阻止会严重影响可用性。
- 录音保存在本地（IndexedDB）后可在网络恢复时自动上传，不影响答题体验。
- 但麦克风等录音能力不可用意味着根本无法完成口语题目，必须阻止。

### 影响页面

- `P-PR-03`（准备与设备检查）：`network` 项失败时标记 `LOCAL_ONLY` 而非 `FAIL`。
- `P-SB-05`（提交前检查）：存在未同步录音时禁用提交按钮，提示「请恢复网络后提交」。
- `P-EX-04`（通用执行器）：离线时顶部黄条提示 `LOCAL_ONLY`。

### 影响契约

- `attempt.deviceCheck.network.status: "PASS" | "LOCAL_ONLY" | "FAIL"`（新增 `LOCAL_ONLY`）
- `POST /api/v1/attempts/{id}/submit` 前置校验：所有录音 `localOnly=false`

### 后续可扩展项

- P1：离线模式下允许提交，后端在录音上传完成后自动触发评分。
- P1：Service Worker 缓存练习内容，支持完全离线答题。

## D09 · 主观题即时反馈

### 决策

- `answerRevealPolicy=IMMEDIATE`（SELF_PRACTICE 模式）下：
  - **只展示 `keyPoints`**（要点列表）。
  - **不直接展示完整 `referenceAnswer`**。
  - 教师发布后可展示示范答案（`referenceAnswer`）。

### 原因

- 立即展示完整示范答案可能诱导学生照抄，丧失思考过程。
- 展示要点列表既提供方向性反馈，又保留学生自主组织语言的空间。

### 影响页面

- `P-EX-04`（通用执行器）：简答题作答后展示 `keyPoints` 而非 `referenceAnswer`。
- `P-RP-07`（正式报告）：教师发布后可切换展示 `referenceAnswer`。

### 影响契约

- `answerRevealPolicy=IMMEDIATE` 行为明确：主观题展示 `keyPoints`，客观题展示 `correctKeys`。
- `referenceAnswer` 的展示需 `teacherPublishedAt` 时间戳（P1 实现）。

### 后续可扩展项

- P1：教师可配置「即时展示 / 延迟展示 / 不展示」三种策略。
- P1：学生提交后 N 分钟自动揭示 `referenceAnswer`（可配置延迟）。

## D10 · ASSIGNMENT 复测需审批

### 决策

- `report.retestEntry.requiresTeacherApproval = true`。
- 学生只能发起复测请求，不能直接创建复测 Attempt。
- 教师审批后系统自动创建 `SELF_PRACTICE` 模式的复测投递。

### 原因

- ASSIGNMENT 模式下的复测可能影响班级统计与进度追踪，需教师知情并批准。
- 直接让学生复测可能导致：多次复测取最高分的不公平行为。

### 影响页面

- `P-RP-07`（正式报告）：「重新测试」按钮改为「申请复测」，点击后展示确认弹窗「将向老师申请复测机会」，提交后按钮变为「已申请，等待审批」。
- 教师端：收到复测申请通知，审批后自动创建 SELF_PRACTICE 投递。

### 影响契约

- `report.retestEntry.requiresTeacherApproval: boolean`（ASSIGNMENT=true, SELF_PRACTICE=false）
- `POST /api/v1/retest-requests`（学生发起，body: `{ attemptId, reason }`）
- `POST /api/v1/retest-requests/{id}/approve`（教师审批，自动创建投递）

### 后续可扩展项

- P1：教师可设定全局策略「允许自由复测 / 需审批 / 不可复测」。
- P1：复测次数限制（每个 Assignment 最多 1 次复测）。
