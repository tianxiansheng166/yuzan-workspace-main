# AI 协作任务模板与验收清单

## 1. 为什么需要这份模板

这次对话已经把产品方向说清楚，但过去容易出现：

- AI 顺着宏大方向再造一套新架构；
- 前端、后端和契约分别猜字段；
- 页面做得完整，数据仍是静态；
- 功能被标成完成，却没有真实测试；
- AI 把“建议”写成“已经实现”。

以后给 AI 的任务必须把“目标、现有事实、范围、用户动作、异常和验收”一次说清。

## 3. AI 开工前必须回答

AI 在改代码前先回答：

1. 当前真实运行入口是什么？
2. 当前页面调用哪个 API？
3. Controller、DTO、OpenAPI 和前端字段是否一致？
4. 数据由谁创建、存在哪个模型？
5. 谁可以读取和修改？
6. 离线、权限不足和供应商不可用时怎样表现？
7. 是否存在硬编码业务数据或固定 demo ID？
8. 本次最小纵向切片是什么？
9. 哪些现有模型会复用？
10. 用什么命令证明完成？

任何一项无法回答，先查代码，不开始铺页面。

## 4. AI 方向讨论的正确用法

方向讨论可以提出：

- 产品定位；
- 用户旅程；
- 领域对象；
- 取舍；
- 阶段目标；
- 风险。

方向讨论不能直接宣称：

- 模块已完成；
- API 已可用；
- 测试已通过；
- 数据模型可以直接迁移；
- 某竞品规则适合本项目；
- AI 评分有效。

每条方向建议应标记为：

| 标记 | 含义 |
|---|---|
| `DECISION` | 已由项目负责人决定 |
| `PROPOSAL` | 候选方案，待评审 |
| `CURRENT_FACT` | 已由当前代码或运行验证 |
| `GAP` | 当前缺口 |
| `EXPERIMENT` | 需要试验和测量 |

## 5. 第一批可直接使用的任务提示词

### 任务 A：契约收敛

```text
目标：让黄金闭环涉及的 Controller、DTO、OpenAPI 和 web-runtime api-client 完全一致。

先检查：
- apps/api/src/modules/assessment
- apps/api/src/modules/recordings
- apps/api/src/modules/speech-job
- apps/api/src/modules/classes
- packages/contracts/openapi/openapi.yaml
- web-runtime/assets/api-client.js
- web-runtime/teacher/assessments/create/app.js
- web-runtime/assessment/assets/app.js

必须解决：
1. ClassAssessmentDto.enrollmentIds 与 service 默认全班规则冲突；
2. 前端不传 questionIds 会创建空 session；
3. 新测评、录音和 speech endpoints 未进入 OpenAPI；
4. 稳定错误码和权限说明缺失。

不得：
- 新增页面；
- 用固定题目填满 session；
- 删除现有持久化模型；
- 把错误改成静默成功。

验收：
- OpenAPI 校验通过；
- DTO/Controller 契约测试；
- 创建有 item 的班级测评；
- 0 item 被拒绝；
- 跨学校题目被拒绝；
- 前端请求 payload 测试。
```

### 任务 B：测试地基修复

```text
目标：修复近期依赖变更造成的测试装配失败，并给新核心模块建立测试基线。

当前基线：
- API typecheck 通过；
- API test：705 通过、57 失败、44 跳过；
- worker typecheck 通过；
- worker test：0 个测试文件。

重点：
- ClassesService 新增 PrismaService/AssessmentService 后的测试 provider；
- Assignments、Submissions、Learning、Reporting 测试 provider；
- DB 测试环境 gate；
- Assessment、Recording、SpeechJob 和 worker 的正常/失败/租户负向测试。

不得：
- 通过删除断言或批量 skip 让数字变绿；
- 把数据库代码错误归为环境错误；
- 把 0 个测试写成测试通过。

验收：
- Node 24；
- 非 DB 单元测试全绿；
- DB 套件状态清楚；
- worker 至少覆盖正常、超时、重复消费、回写失败。
```

### 任务 C：第一份练习定义

```text
目标：用现有 CourseVersion/LearningActivity/Question 与最小新增练习模型，建立“古诗文朗读与理解训练 v1”。

必须包含：
- PracticeDefinition/Version/Section/ItemRef/RubricVersion；
- 2 个以上口语 section；
- 1 个书面 section；
- 播放、准备、录音、重录规则；
- 能力标签；
- 内容来源和版权状态；
- 已发布版本不可修改；
- 跨学校负向测试。

不得：
- 建立与 Question 完全重复的新题库；
- 将练习内容写在前端；
- 使用真实学生数据；
- 使用未经登记的音频或生成图片。
```

### 任务 D：学生通用执行器

```text
目标：把 web-runtime/assessment 的执行流程改为完全由 PracticeVersion 和 Attempt 数据驱动。

必须：
- 动态 session/item；
- 正常、加载、空、错误、离线、权限和 provider 状态；
- 真实设备检查；
- 录音本地状态与服务端上传状态分离；
- 书面草稿 revision；
- 提交检查；
```

## 6. AI 交付审查表

### 产品

- [ ] 是否只解决一个清楚的用户动作？
- [ ] 是否属于黄金闭环？
- [ ] 是否复用统一练习模型？
- [ ] 是否避免新增无关页面？

### 数据

- [ ] 数据是否来自真实 API？
- [ ] 是否存在默认硬编码业务数据？
- [ ] 是否保存版本和快照？
- [ ] 是否有迁移和回滚？

### 前后端

- [ ] OpenAPI、DTO、Controller、客户端一致？
- [ ] ID 类型有没有混用？
- [ ] 空状态会不会创建假内容？
- [ ] API 失败是否真实显示？

### 安全

- [ ] 学校范围由服务端校验？
- [ ] 学生只能访问自己？
- [ ] 教师只访问授权班级？
- [ ] worker 内部回写 fail closed？
- [ ] 敏感数据未进入日志和截图？

### 状态

- [ ] loading
- [ ] normal
- [ ] empty
- [ ] error
- [ ] offline
- [ ] permission
- [ ] processing
- [ ] provider unavailable

### 验证

- [ ] 实际运行 typecheck？
- [ ] 实际运行相关测试？
- [ ] 记录通过、失败和跳过数字？
- [ ] 有跨租户负向测试？
- [ ] 有 1440、1024、390 截图？
- [ ] 0 测试没有被写成通过？

## 7. 陌生读者检查问题

每次完成一份重要文档或任务交接，用全新对话询问：

1. 这个项目当前唯一 P0 是什么？
2. 为什么不能继续铺页面？
3. `web-runtime` 当前是什么技术形态？
4. 自主练习与阶段测评如何复用同一内核？
5. 当前已有后端模型哪些复用，哪些最小新增？
6. 为什么现在不能优先做 AI 备课 Agent？
7. 一项功能怎样才算真实完成？
8. worker 未配置供应商时前端怎样显示？
9. 如何证明没有跨学校或跨学生访问？
10. 未来 20 个工作日的最终交付是什么？

如果读者不能只凭文档回答，说明文档仍缺事实或边界。
