# 00 页面族信息架构

## 页面族唯一主线

```text
S01 发现可做内容
→ S02 理解目标与规则
→ S03 建立可执行环境
→ S04 完成听、说、读、写证据
→ S05 核对完成与同步
→ S06 等待机器处理或教师复核
→ S07 读懂证据与下一步
→ S08 回看自己的声音证据
→ S09 对照历次变化并决定复测
```

S07 可返回 S01，可进入 S08 或 S09；S09 的事件可回到 S07。任何页面都不得让学生直接穿过设备检查、未同步证据或未完成报告守卫。

## 信息架构原则

1. 每页只回答任务定义中的一个核心问题，主操作不超过一个决策组。
2. 身份、学校、班级、练习、版本、投递、Attempt 与证据保持同一 Fixture 引用。
3. 技术 ID、接口状态、错误码放入可折叠“设计检查面板”，不进入学生主体。
4. 本地保存、上传中、服务端已同步、评分处理中和报告完成是不同事实。
5. 不以接口缺失删除页面；用接口状态与正式实现阻塞项表达缺口。
6. 视觉层级按“当前任务 → 必要证据 → 次要说明 → 技术检查”递减，不做卡片墙。

## 核心对象在页面族中的生命线

| 对象 | 首次出现 | 主要消费 | 结束状态 |
| --- | --- | --- | --- |
| PracticeDefinition | S01 | S02、S09 | 稳定身份 |
| PracticeVersion | S02 | S03、S04、S05 | PUBLISHED 快照 |
| PracticeDelivery | S01 | S02、S03 | Attempt policySnapshot |
| Attempt | S03 | S04—S09 | COMPLETED |
| Section / ItemAttempt | S04 | S05—S07 | FINALIZED/AUTO_RESULT/REVIEWED |
| Recording / SpeechJob | S04 | S05、S06、S07、S08 | UPLOADED/FINALIZED |
| Review / Report | S06 | S07、S09 | 审阅后可追溯 |
| Consolidation suggestion | S07 | 学习计划/下一练习 | 教师确认后可执行 |

## 导航守卫

| 目标 | 前置事实 | 不满足时 |
| --- | --- | --- |
| S02 | 当前学生可见 Delivery | 回 S01，说明尚未开放 |
| S03 | 已发布版本、允许开始 | 留在 S02，显示真实原因 |
| S04 | Attempt 属于本人且状态可执行；设备阻塞项通过 | 留在 S03 或跳 S06/S07 |
| S05 | 至少进入过 S04 | 跳当前未完成 Item |
| S06 | Attempt 已 SUBMITTED | 回 S05 |
| S07 | 正式报告可读且数据足够 | S06 或数据不足状态 |
| S08 | 录音属于本人 | permission，不泄露存在性 |
| S09 | 当前学生本人历史 | empty 或 permission |

## 视口策略

- 1440：完整工作区，最大内容宽 1200，充分利用横向关系，不铺满同权卡片。
- 1024：双栏转主次上下或窄双栏；固定操作不遮挡内容。
- 390：信息顺序重构为单列，触控热区至少 44×44；S03/S04/S05 明确正式执行需电脑或平板，线框只展示结构与状态。
