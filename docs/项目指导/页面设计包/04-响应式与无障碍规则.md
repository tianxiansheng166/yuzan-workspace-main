# 04 响应式与无障碍规则

## 断点与重排

| 视口 | 内容区 | 重排规则 |
| --- | --- | --- |
| 1440 | 最大 1200px | 12 列；主任务占 7—8 列，次要摘要占 4—5 列 |
| 1024 | 左右各 32px | 8 列；并列区按阅读顺序转上下 |
| 390 | 左右各 16px | 4 列；底部固定操作预留安全区，不做固定画布缩放 |

390 验收截图同时验证信息结构与 Delivery 决策。不得笼统禁止 S03/S04/S05：允许时保留完整设备检查、听音、录音、书面答案、本地保存和提交检查；阻塞时显示具体 DeliveryPolicy 原因与建议设备。移动录音控件必须重新编排，不得缩放桌面控件。S06 可以移动查看处理状态。

## Delivery 模式与手机执行

| 模式 | 390 执行规则 | 阻塞表达 |
| --- | --- | --- |
| SELF_PRACTICE | 浏览器支持麦克风、音频播放、本地存储时允许执行 | 只按真实能力逐项阻塞，不使用笼统设备禁令 |
| COURSE_PRACTICE | 默认允许；DeliveryPolicy 可限制 | 显示策略给出的具体原因与建议设备 |
| ASSIGNMENT | 教师发布时的 DeliveryPolicy 决定 | 未指定时不得推断允许；不允许时显示具体原因与建议设备 |
| STAGE_ASSESSMENT | P0 可看测评信息，不可手机正式作答 | 固定文案“本次阶段测评需要使用电脑或平板”，且不进入设备录音流程 |

## 可访问性

- 文字与背景对比至少 4.5:1；大字至少 3:1。
- 可点击区域移动端至少 44×44，桌面按钮至少 36 高。
- 颜色不是唯一状态信号；同时使用文案、形状和 `aria-label`。
- 进度用 `<progress>` 或带 `aria-valuenow` 的语义元素。
- 音频控制提供播放状态、剩余次数和文本说明；不自动播放。
- 录音倒计时、开始、停止、保存、上传结果均由 live region 宣告。
- 波形为装饰时 `aria-hidden=true`；证据含义用文字提供。
- 表格在 390 转为带字段名的定义列表，不隐藏关键列。
- 输入错误与字段建立 `aria-describedby` 关联。
- 焦点可见轮廓不小于 2px；键盘可完成所有非录音硬件动作。
- `prefers-reduced-motion: reduce` 时取消非必要动效。

## 页面级响应

| 页面 | 1440 | 1024 | 390 |
| --- | --- | --- | --- |
| S01 | 入口主区 + 截止/继续摘要 | 两区上下 | 单列任务流 |
| S02 | 目标正文 + 练习结构 | 概要下移 | 单列、开始按钮吸底 |
| S03 | 四项设备检查 + 说明 | 2×2 | 允许时完整四项检查与进入动作；阻塞时只看 Delivery 信息，不进入录音检查 |
| S04 | 专注任务区 + 题侧栏 | 侧栏下移 | 允许时提供移动专用听音/录音/作答控件；阻塞时不渲染可执行任务区 |
| S05 | 证据清单 + 提交门槛 | 摘要下移 | 允许时完整核对与提交；阻塞模式不应从 S04 到达 |
| S06 | 中央处理路径 | 同结构 | 单列完整适配 |
| S07 | 报告证据 + 下一步 | 纵向分区 | 总结优先，图表可横滚 |
| S08 | 录音档案 + 播放详情 | 上下结构 | 列表优先 |
| S09 | 时间轴 + 趋势 | 上下结构 | 纵向时间轴 |
