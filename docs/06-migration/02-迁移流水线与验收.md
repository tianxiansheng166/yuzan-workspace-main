# 迁移流水线与验收

## 目录

```text
legacy/
├─ source-archives/    原始压缩包，只读
├─ manifests/          校验和、文件清单、复用判定
├─ exports/            从旧项目导出的中间文件
├─ review/             内容/隐私/版权审核结果
└─ reports/            每次迁移报告
```

## 流程

1. 计算原始压缩包 SHA-256。
2. 在隔离环境解压，不运行未知脚本。
3. 文件分类：代码、配置、数据、媒体、文档。
4. 扫描 secret、个人信息、外链和许可证。
5. 导出候选数据到 JSONL/CSV。
6. 使用独立 mapping 文件转换到新 schema。
7. 使用 Zod/JSON Schema 校验。
8. 导入临时 PostgreSQL。
9. 校验引用、重复、枚举、媒体校验和和版权状态。
10. 输出 accepted/rejected/warning 报告。
11. 教研、产品、技术签字。
12. 进入 seed 或试点数据；原始档案继续只读。

## 验收

- 输入、脚本版本、输出和错误可重现；
- 不输出明文密码/token；
- 用户数据默认拒绝，不“顺便保留”；
- 课程数量、版本和资源引用有前后对账；
- 导入脚本可重复运行且不会创建重复记录；
- 迁移报告进入 Git，但敏感原始数据不进入 Git。
