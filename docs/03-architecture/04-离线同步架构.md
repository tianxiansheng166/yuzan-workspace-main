# 离线优先与同步架构

## 离线不是“缓存几个页面”

必须覆盖：

- 用户已授权的任务元数据；
- 课程资源及校验和；
- 活动进度；
- 客观题草稿；
- 录音文件与上传状态；
- 提交回执；
- 服务端变更和冲突。

## 客户端存储

IndexedDB 建议 store：

- `contentPackages`
- `resources`
- `assignments`
- `activityProgress`
- `draftAnswers`
- `audioBlobs`
- `outboxOperations`
- `syncReceipts`
- `deviceState`

敏感数据最小化；登出、账号切换和设备共享场景必须明确清理策略。

## Outbox 操作

```json
{
  "operationId": "client-generated-uuid",
  "entityType": "submission",
  "entityId": "...",
  "action": "submit",
  "baseRevision": 3,
  "payload": {},
  "createdAt": "...",
  "attempts": 0
}
```

## 服务端处理

- 对 `operationId` 幂等；
- 校验用户、学校、任务和资源范围；
- 比较 revision；
- 成功返回服务端 revision 和 receipt；
- 可自动合并的进度采用单调规则；
- 不能安全合并的答案/反馈进入冲突队列；
- 永不采用“最后写入者覆盖一切”作为默认。

## 冲突策略示例

| 数据 | 策略 |
|---|---|
| 视频观看位置 | 在同一活动内取更大位置，但不自动标记完成 |
| 客观题草稿 | 未提交前可按字段时间合并 |
| 已提交答案 | 不覆盖，生成新 attempt 或人工选择 |
| 教师反馈 | revision 冲突必须人工重载 |
| 课程版本 | 不合并，重新下载新包 |
| 语音文件 | 以唯一录音 ID 保存，不覆盖 |

## 验收场景

- 下载后进入飞行模式并完成任务；
- 浏览器被关闭后恢复；
- 同一操作重试十次不重复创建；
- 两台设备修改同一草稿；
- 服务器在同步中途返回 500；
- 资源校验和不一致；
- 设备存储空间不足；
- 账号在共享设备上切换。
