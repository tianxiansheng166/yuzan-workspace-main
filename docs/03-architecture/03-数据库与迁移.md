# 数据库与迁移策略

## PostgreSQL 原则

- 所有业务表带明确主键、时间戳和必要外键；
- 多租户核心表显式存 `school_id`；
- 唯一约束表达业务不变量，而不只依赖应用检查；
- 软删除只在业务需要恢复/审计时使用，不能成为默认；
- JSONB 仅用于低稳定度扩展字段，不代替关系建模；
- 迁移必须可审查、可在测试库执行并有回滚/前滚方案。

## Prisma 使用

- `infra/database/prisma/schema.prisma` 是当前数据模型基线；
- 只由 Schema Owner 合并修改；
- 业务 AI 提交 schema change request，不直接多人并发改同一文件；
- migrations 进入 Git；
- seed 仅生成虚构数据，不包含真实学生信息。

## 旧 JSON 数据

不长期双写。流程：

1. 原始压缩包校验并只读归档；
2. 导出到临时 JSONL/CSV；
3. 脱敏和字段映射；
4. 使用新 schema 校验；
5. 导入隔离测试库；
6. 生成逐类成功/拒绝/警告报告；
7. 人工确认后进入试点；
8. 旧数据不再被新应用读取。

## 备份恢复

试点前必须完成：

- 每日自动备份；
- 加密和访问控制；
- 恢复到隔离环境演练；
- 记录 RPO/RTO 实测；
- 对象存储与数据库引用一致性检查；
- 删除请求和保留期策略。
