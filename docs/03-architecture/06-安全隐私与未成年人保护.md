# 安全、隐私与未成年人数据

## 数据最小化

MVP 默认不收集身份证、精确地址、民族、家庭经济情况等高敏感字段。每个新增字段必须记录：

- 业务目的；
- 法律/授权依据；
- 使用角色；
- 保留期限；
- 是否进入导出/报表；
- 删除和更正方式。

## 身份与会话

- 密码使用现代自适应哈希；
- JWT/会话密钥只能来自 secret manager/环境；
- 短期访问令牌 + 可撤销刷新会话；
- 登录、重置、导出和高风险操作限流；
- 管理操作支持 MFA（试点后按风险开启）；
- CORS 使用明确允许列表；
- Cookie 场景启用 Secure/HttpOnly/SameSite 与 CSRF 防护。

## 文件与音频

- 文件头与 MIME 双重检查；
- 病毒/恶意内容扫描；
- 对象存储私有桶；
- 短期签名 URL；
- 音频保留期限和删除策略；
- 不将原始音频写入普通日志或分析事件。

## 多租户和授权

- 所有服务层查询带学校范围；
- 对象存储 key 也按租户隔离；
- 关键路径做跨租户负向测试；
- 支持对异常管理员访问进行审计。

## 授权矩阵

MVP 使用静态角色-权限矩阵。当前可执行角色以 Prisma 冻结枚举中的有效值为限，由低到高依次为：STUDENT、TEACHER、SCHOOL_ADMIN、PLATFORM_ADMIN。

| 角色           | 拥有的原子权限                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| STUDENT        | `assignment:submit`、`progress:read:own`、`content:read`                                                              |
| TEACHER        | `course:manage`、`assignment:manage`、`assignment:review`、`feedback:provide`、`content:read`                         |
| SCHOOL_ADMIN   | `school:members:manage`、`school:classes:manage`、`school:courses:manage`、`school:reports:read`，并继承 TEACHER 权限 |
| PLATFORM_ADMIN | `platform:schools:manage`、`platform:audit:read`                                                                      |

RESEARCHER 虽然在 Prisma `MembershipRole` 枚举中作为保留值存在，但不是当前可执行角色，不会通过认证守卫，也不会在默认矩阵中获得任何权限。研究访问属于未来独立授权机制；在模型、契约和隐私审批完成前，默认拒绝。

未来可以保留 guard 接口不变，将矩阵替换为数据库驱动或策略引擎。

## 角色与租户边界

- **学生**：只能访问本人学习数据、本人作业与测评；不能访问其他同学数据。
- **教师**：只能访问本校课程、作业、提交、反馈与报告；不能访问其他学校数据。
- **学校管理员**：只能管理本校成员、班级、课程与报告；不能管理其他学校。
- **平台管理员**：通过平台级端点管理学校与审计日志；不默认访问学校内教学资源。
- **跨租户拒绝**：任何请求中 `schoolId` 与当前租户 `schoolId` 不一致时，一律返回 403。
- **缺失租户 / 未知角色**：一律拒绝，不降级为默认权限。

## 统一错误码

所有安全错误通过 `SecurityException` 抛出，全局异常过滤器统一渲染为 `{ code, message }`：

| 错误码                 | HTTP 状态 | 含义                             |
| ---------------------- | --------- | -------------------------------- |
| `UNAUTHENTICATED`      | 401       | 未认证或成员状态非 ACTIVE        |
| `MISSING_TENANT`       | 401       | 请求缺少租户上下文               |
| `UNKNOWN_ROLE`         | 401       | 主体包含未知或无效角色           |
| `FORBIDDEN_TENANT`     | 403       | 请求资源所属学校与当前租户不一致 |
| `FORBIDDEN_ROLE`       | 403       | 当前角色无权执行                 |
| `FORBIDDEN_PERMISSION` | 403       | 缺少所需原子权限                 |
| `FORBIDDEN_OWNERSHIP`  | 403       | 资源级策略拒绝（如不是本人提交） |

## 可复用接口

GOV-006 为 IDN-001、ORG-001、CUR-001 等后续任务提供以下可复用接口：

- `@Public()`：标记公开路由，跳过认证与租户校验。
- `@RequireRoles(...roles)`：要求至少具备一个指定角色。
- `@RequirePermissions(...permissions)`：要求至少具备一个指定权限。
- `@CurrentPrincipal()`：注入当前主体（userId、roles、membershipStatus、source）。
- `@CurrentTenant()`：注入当前租户上下文（schoolId）。
- `AuthContextSource`：认证上下文解析抽象；IDN-001 提供真实实现替换 Stub。
- `ResourcePolicy<T>`：资源级策略接口，用于细粒度所有权/访问规则。

`AuthModule` 通过 `APP_GUARD` 全局注册 `AuthenticationGuard`、`TenantAuthorizationGuard`、`PolicyGuard`。当前 GOV-006 不将 `AuthModule` 导入根 `AppModule`，因此基线已连线但尚未全局启用；待后续任务接入后自动生效。

- `GLOBAL_WIRING_STATUS=pending`
- `APP_MODULE_CHANGE_REQUIRED=yes`
- `MAIN_TS_CHANGE_REQUIRED=no`

`AuthModule` 的默认 `AuthContextSource` 为 `DenyAllAuthContextSource`，始终返回未认证。即使 `AuthModule` 被意外导入根模块，也不会因为客户端伪造 Header 而获得身份。`StubAuthContextSource` 仅用于测试显式覆盖，不得作为生产身份源。

## 日志脱敏清单

`redact()` 函数会递归检查结构化日志字段名，命中以下模式时替换为 `[REDACTED]`：

- 认证与凭据：`password`、`passwordHash`、`token`、`accessToken`、`refreshToken`、`authorization`、`apiKey`、`secret`、`credential`、`session`。
- 学生 PII：`displayName`、`realName`、`phone`、`email`、`idCard`、`address`、`audio`、`recording`、`avatar`、`profile`。

注意：调用方不应将原始 secret 字符串作为独立日志 payload 传入；`redact()` 主要处理结构化对象。

## 录音 / 测评 / 报告访问边界

- **原始音频**：仅学生本人、其授权教师及学校管理员可访问；研究人员只能接触去标识化后的分析结果。
- **测评详情**：学生可读本人测评；教师可读本校学生测评；跨学校访问拒绝。
- **学习报告**：学生/家长可读本人；教师可读本校学生；学校管理员可读全校汇总；研究人员仅在去标识化后可读聚合报告。
- **禁止行为**：不得将原始音频、完整测评录音或学生 PII 写入普通应用日志或分析事件。

## 未成年人数据最小化清单

在 MVP 范围内，新增任何涉及未成年人的字段前必须确认：

1. 是否必须用于当前教学/测评流程；
2. 是否已获得监护人同意或学校授权；
3. 哪些角色可以在什么场景下访问；
4. 保留期限与自动删除策略；
5. 是否会进入导出、报表或第三方系统；
6. 学生/监护人是否有权查阅、更正与删除。

## 安全门禁

- SAST、依赖漏洞、secret scan；
- OWASP API 风险测试；
- 上传、IDOR、越权、速率限制；
- 备份恢复；
- 日志脱敏；
- 安全事件响应联系人和流程。

正式试点前必须由具备资质的法律/安全人员结合部署地区和实际数据重新审查。
