# 目标技术架构

## 1. 总体形态

采用模块化单体而不是过早微服务：

```text
Browser / Installed PWA
        │ HTTPS / OpenAPI
        ▼
Nuxt Web ─────────────── NestJS API
                              │
               ┌──────────────┼──────────────┐
               ▼              ▼              ▼
          PostgreSQL     Object Storage     Worker
               │                              │
               └──── transactional outbox ────┘
```

可选组件：

- Redis/队列：只有异步量和重试需求出现后启用；
- 校内边缘节点：完成云端闭环与离线同步后，以部署配置加入；
- CDN：用于有授权的静态资源，不作为业务数据源。

## 2. Monorepo

```text
yuzan-next/
├─ apps/
│  ├─ web/       Nuxt 4 + Vue 3 + PWA
│  ├─ api/       NestJS 11
│  └─ worker/    异步处理
├─ packages/
│  ├─ contracts/ OpenAPI、生成类型与共享 DTO
│  ├─ domain/    纯领域类型、枚举和规则
│  ├─ ui/        设计 token 与无业务组件
│  ├─ config/    ESLint/TS/环境配置
│  └─ test-utils/
├─ infra/
│  ├─ database/
│  ├─ storage/
│  ├─ docker/
│  └─ monitoring/
└─ tests/
   ├─ contract/
   ├─ e2e/
   ├─ security/
   └─ performance/
```

## 3. NestJS 模块

- identity
- organizations
- classes
- curriculum
- resources
- assignments
- learning
- assessment
- speech
- sync
- reporting
- audit
- health

模块之间不直接访问彼此的 Prisma 表；通过应用服务或公开端口交互。首期仍是一个部署单元，避免分布式复杂度。

## 4. Nuxt 前端切片

前端按用户任务而非技术组件组织：

- `features/auth`
- `features/today`
- `features/curriculum-studio`
- `features/assignment-builder`
- `features/learning-player`
- `features/submission-review`
- `features/sync-center`
- `features/reports`

`packages/ui` 只放通用视觉原语，不放“课程卡片”这类业务组件。

## 5. 架构质量属性

优先级：

1. 数据隔离与正确性；
2. 弱网可用和可恢复；
3. 可维护和可测试；
4. 可观测和可回滚；
5. 性能；
6. 水平扩展。

禁止为了“架构先进”牺牲前四项。
