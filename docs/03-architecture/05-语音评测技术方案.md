# 语音学习与评测技术方案

## 目标边界

第一期不是宣称“实时精准纠正所有藏汉发音”，而是完成可评测的最小闭环：

```text
指定文本朗读
→ 本地录音质量检查
→ 上传/边缘处理
→ ASR 或强制对齐
→ 完整度、流利度、停顿与可用的发音特征
→ 置信度与问题片段
→ 教师复核
→ 学生可行动反馈
```

## 三级执行

### 设备端

- 权限与设备检测；
- 音量、静音、截断、时长、明显噪声检查；
- VAD 分段；
- 离线保存和重试；
- 不依赖云端的录音指导。

### 校内节点（后续）

- 局域网内容分发；
- 缓存上传；
- 轻量识别/对齐；
- 与云端延迟同步。

### 云端

- 供应商/模型适配；
- 深层分析；
- 教师复核；
- 评测数据集与版本管理。

## Provider Adapter

业务层只依赖统一接口：

```ts
interface SpeechProvider {
  analyze(input: {
    audioObjectKey: string;
    targetText: string;
    locale: string;
    dialect?: string;
  }): Promise<ProviderSpeechResult>;
}
```

记录：

- provider、model/version；
- 输入音频校验和；
- target text version；
- 处理耗时；
- 原始输出安全摘要；
- 失败原因和重试；
- 成本；
- 最终教师修正。

## 评测

建立带教师双人标注的数据集，按年级、性别、地区/方言、设备和噪声分层。至少测：

- 字/音节错误率或对齐成功率；
- 音频拒绝率；
- 处理 P50/P95；
- 模型大小和设备内存；
- 自动分与教师分的相关性/一致性；
- 不同分组的差异；
- 低置信度覆盖率。

没有完成评测前，学生端只展示保守反馈，教师端显示“自动建议”而非“权威评分”。
