# 可观测性与运维

本文档定义语赞心声（Yuzan）部署、健康检查、日志、指标、告警与隐私保护的运维基线。

## 1. 范围与约束

- 本任务仅覆盖 `infra/**`、`apps/api/src/health/**`、`packages/observability/**` 与本文档。
- 不修改 `apps/api/src/app.module.ts`、`apps/api/src/main.ts`、`package.json`、`pnpm-lock.yaml` 等禁止路径。
- 新的健康模块当前未接入根模块，需后续任务接线；状态见文末 `ROOT_WIRING_STATUS`。
- 所有示例配置均使用占位变量，不得直接用于生产。

## 2. 健康检查

### 2.1 端点

| 端点                       | 作用      | 是否公开 | 说明                                           |
| -------------------------- | --------- | -------- | ---------------------------------------------- |
| `GET /api/v1/health/live`  | liveness  | 是       | 仅证明进程与事件循环可响应                     |
| `GET /api/v1/health/ready` | readiness | 是       | 返回依赖整体状态；503 表示不可接收流量         |
| startup                    | 内部状态  | 否       | 用于冷启动、配置加载、迁移等待；不新增公开端点 |

### 2.2 Liveness

- 仅检查当前进程与事件循环。
- 不访问数据库、MinIO、AI 服务、消息队列，不执行网络调用。
- 返回字段：`status`、`timestamp`、`service`、`uptimeMs`。
- 不返回主机名、绝对路径、连接串、堆栈或环境变量。

### 2.3 Readiness

依赖状态统一为：`healthy`、`degraded`、`unavailable`、`timeout`、`unknown`、`not-configured`。

至少支持以下依赖类别：

- `database`
- `object-storage`
- `message-queue`
- `ai-service`

当前没有真实 adapter 时：

- 不伪造 `healthy`。
- 无 checker 的依赖返回 `not-configured`。
- 生产模式下必要依赖未配置导致整体 not-ready。
- 可选依赖失败导致 `degraded`，不影响整体 ready 状态。

每项依赖检查支持超时；多依赖并行检查；单个挂起依赖不会永久阻塞。响应中不直接返回原始 `Error.message`、主机名、端口、bucket、数据库名、凭据或连接串。

### 2.4 Startup

- 内部状态模型：`starting`、`ready`、`failed`。
- startup 与 liveness 分离；启动中进程仍可存活。
- 启动失败不能被表示为 ready。
- 不自动执行真实数据库迁移，不修改 Prisma，不新增高风险启动副作用。

## 3. 可复用可观测性包

`packages/observability` 提供以下边界：

- **context**：基于 `AsyncLocalStorage` 的轻量上下文，含 `requestId`、`correlationId`、`safeTenantRef`、`safeUserRef`、`service`、`environment`。
- **logger**：基于 pino 的结构化日志，自动从 context 注入 requestId 等字段。
- **redaction**：递归脱敏，覆盖对象、数组、Header、URL query、Error cause、request body 摘要。
- **metrics**：`Counter`、`Gauge`、`Histogram`、`Registry`，支持 label 白名单、长度与数量限制。
- **shutdown**：优雅关闭协调器，支持顺序/并行策略、超时、错误汇总、重复调用防护。

### 3.1 日志字段

每条日志至少可包含：

- `timestamp`
- `level`
- `service`
- `environment`
- `event`
- `requestId`
- `correlationId`
- `safeTenantRef`
- `safeUserRef`
- `durationMs`
- `status`

### 3.2 脱敏规则

大小写不敏感屏蔽以下 key：

`authorization`、`cookie`、`set-cookie`、`password`、`passcode`、`token`、`accessToken`、`refreshToken`、`secret`、`apiKey`、`clientSecret`、`audio`、`audioContent`、`recording`、`studentName`、`studentAnswer`、`answerText`、`prompt`、`transcript`。

URL query 中以下参数被替换：

`token`、`access_token`、`code`、`password`、`secret`。

脱敏实现：

- 递归处理嵌套对象与数组。
- 处理 Header、Error cause、Error details。
- 避免循环引用导致崩溃。
- 不修改原输入。

### 3.3 指标规则

- 重复注册相同定义安全；同名不同定义拒绝。
- label 名白名单通过声明控制；非法 label 拒绝。
- label 值长度上限 256，label 数量上限 16。
- 不允许动态任意 label。
- 禁止 PII label：`studentId`、`email`、`token`、`requestId`、`authorization`、`cookie`。
- `route` label 必须使用模板路径，不得使用完整 URL。
- `tenant` 不作为默认高基数 label。

## 4. 部署基线

示例配置位于 `infra/deployment/**` 与 `infra/deployment/k8s/**`。

### 4.1 容器安全

- 非 root 用户运行。
- 只读根文件系统。
- `/tmp` 等临时目录显式挂载。
- 资源 requests/limits 明确。
- capabilities 全部 drop。
- 不允许特权提升。

### 4.2 Probe 建议

- liveness：`/api/v1/health/live`，不依赖外部服务。
- readiness：`/api/v1/health/ready`。
- startup：`/api/v1/health/live`，用于冷启动保护。

### 4.3 优雅关闭

- 监听 SIGTERM。
- `terminationGracePeriodSeconds` 60 秒。
- `preStop` sleep 10 秒，便于负载均衡器停止转发。
- 库代码中不直接调用 `process.exit`。

### 4.4 Secrets

- 通过 Kubernetes Secret 外部注入。
- 不提交 `.env`。
- 不硬编码生产域名、账号、密码。
- 开发 compose 使用占位密码；生产与开发配置分离。

### 4.5 日志与数据

- 容器日志输出到 stdout/stderr。
- 数据持久化位置明确（Postgres、MinIO volumes）。
- 备份恢复责任由运维团队承担，具体策略由组织政策决定。

## 5. 告警与 SLI/SLO

### 5.1 SLI

- availability
- request error rate
- latency
- readiness
- dependency availability
- sync failure
- background job failure

### 5.2 SLO 建议（示例）

| SLI          | 窗口 | 目标  | 适用服务 | 不适用           | 环境差异              |
| ------------ | ---- | ----- | -------- | ---------------- | --------------------- |
| availability | 30d  | 99.9% | API      | 计划内维护       | demo 可用性目标可降低 |
| error rate   | 5m   | <2%   | API      | 低流量场景       | demo 允许更高阈值     |
| p95 latency  | 5m   | <1s   | API      | 离线批处理       | demo 放宽至 2s        |
| readiness    | 1m   | 100%  | API      | 依赖自身维护窗口 | demo 可降低           |

> 最终保留周期与目标由组织政策和法律要求确认。

### 5.3 告警分级

- **P1**：服务不可接流量、高错误率、日志脱敏违规。
- **P2**：高延迟、依赖不可用、同步失败突增。
- **P3**：队列积压、非关键资源告警。

所有告警规则包含：持续时间、影响范围、最小请求量门槛、恢复条件、runbook 入口、误报抑制说明。

## 6. 隐私与未成年人保护

- 生产日志不是学生内容仓库。
- 不记录录音正文、书面答案全文、完整 AI 输入、学生姓名、手机号、邮箱、身份证。
- request body 默认不记录；需要摘要时必须先脱敏。
- 敏感错误只保留安全错误码。
- 审计日志与应用日志分离。
- 日志导出需审批。
- 比赛演示不得使用真实学生数据。

### 6.1 建议保留周期

| 环境 | 应用日志 | 审计日志 | 采样/脱敏                          |
| ---- | -------- | -------- | ---------------------------------- |
| 开发 | 7 天     | 30 天    | 允许明文调试，但不得含真实学生数据 |
| 测试 | 14 天    | 90 天    | 必须脱敏                           |
| 生产 | 30 天    | 1 年     | 必须脱敏，PII 不得落盘             |

## 7. 接线状态

- `ROOT_WIRING_STATUS=pending`：新 `apps/api/src/health` 模块尚未接入 `AppModule`。
- `STARTUP_WIRING_STATUS=pending`：startup 为内部服务，未新增公开端点。
- `STARTUP_PUBLIC_ENDPOINT_STATUS=not_declared`：OpenAPI 未声明 startup 公开端点。
- `SCOPE_CHANGE_REQUIRED=yes`：需后续任务修改 `app.module.ts` 与 `apps/api/package.json`（加入 `@yuzan/observability`）才能正式启用新可观测性能力。
