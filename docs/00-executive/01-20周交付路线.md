# 20 周交付路线与门禁

时间仅用于排布，不代表可以跳过质量门禁。多人/多 AI 并发可以缩短等待时间，但不能压缩领域确认、试点和语音校准所需的真实周期。

## Phase 0：治理与安全（第 1–2 周）

交付：

- 新仓库、CI、分支保护、环境配置；
- OpenAPI 与 Prisma 基线；
- 租户、用户、角色、审计和错误规范；
- 旧项目脱敏、校验和与迁移清单；
- 设计 token 和可访问性基线。

退出门禁：

- `lint + typecheck + unit + build` 全部通过；
- API 不公开项目根目录；
- 不存在默认 JWT 密钥；
- 学生数据不再以明文样例进入仓库；
- 共享契约通过架构、前端、后端三方审查。

## Phase 1：内容与身份底座（第 3–6 周）

交付：

- 学校、成员、班级、学期；
- 课程、版本、单元、课时、活动、资源；
- 内容草稿/审核/发布；
- 登录、会话、数据范围权限；
- 新设计系统的基础页面框架。

退出门禁：

- 教研可发布不可变课程版本；
- 发布后修改必须创建新版本；
- 权限矩阵自动化测试通过；
- 课程管理不依赖假数据。

## Phase 2：首个教学闭环（第 7–12 周）

交付：

- 教师创建任务并指定班级；
- 学生今日任务、学习活动、练习和提交；
- 自动保存、断点续学、教师反馈；
- 基础事件采集与班级完成率；
- 关键页面桌面/移动视觉完成。

退出门禁：

- 从建课到反馈的 E2E 全链路通过；
- 学生不能查看或修改他人提交；
- 每个业务状态有 loading/empty/error/permission 设计；
- 真实数据库贯通，不允许前端硬编码业务结果。

## Phase 3：离线与语音 MVP（第 13–16 周）

交付：

- 内容包下载、存储预算和版本校验；
- 本地 outbox、幂等同步、冲突记录；
- 录音质检、ASR/对齐、初步评分和教师复核；
- 同步和语音任务可观测性。

退出门禁：

- 飞行模式 E2E：下载→断网学习→提交→联网同步；
- 重复同步不产生重复业务记录；
- 语音结果显示置信度和原始录音；
- 完成基线模型/供应商评测报告；
- 不宣称超过证据的数据准确率。

## Phase 4：报告、试点与比赛证据（第 17–20 周）

交付：

- 学生成长和教师干预报告；
- 管理员使用与同步报表；
- 备份恢复、安全测试和性能基线；
- 试点操作手册、培训与反馈；
- 比赛演示环境和可验证证据包。

退出门禁：

- 指标口径有 SQL/事件来源；
- 备份恢复演练成功；
- 至少一个试点班级或受控模拟班级连续运行；
- 比赛演示使用真实数据链，而不是静态大屏。
