# 核心实体字段字典

以下是 MVP 最小字段，不是完整数据库文档；最终以 Prisma schema 和迁移为准。

## School

- `id`
- `name`
- `code`
- `status`
- `timezone`
- `region_code`
- `created_at`

## User

- `id`
- `display_name`
- `login_identifier`
- `password_hash`
- `status`
- `preferred_locale`
- `created_at`

敏感信息不得为了“以后可能用”而收集。民族、住址、身份证、监护人信息不进入 MVP，除非有明确合法依据和业务必要性。

## Membership

- `user_id`
- `school_id`
- `role`
- `status`
- `joined_at`

唯一约束：`(user_id, school_id, role)`。

## Class / Enrollment

- `Class`: school, term, name, grade, lead_teacher
- `Enrollment`: class, user, type(student/teacher), status

## Course / CourseVersion

- `Course`: 稳定身份、标题、适用范围、所有者
- `CourseVersion`: version, status, objectives, locale/dialect metadata, published_at
- `Unit`, `Lesson`, `LearningActivity`: 有序结构
- `Resource`: 对象存储键、媒体类型、大小、校验和、版权和离线策略

## Assignment

- `school_id`
- `course_version_id`
- `created_by_user_id`
- `title`
- `starts_at`
- `due_at`
- `completion_rule`
- `offline_required`
- `status`
- `revision`

任务不再直接保存 `class_id`；投放目标统一由 `AssignmentTarget` 承载。

## Submission

- `school_id`
- `assignment_id`
- `enrollment_id`
- `attempt_no`
- `status`
- `submitted_at`
- `revision`
- `device_id`
- `idempotency_key`（必填）

`enrollment_id` 将提交绑定到学校内具体班级身份，而不是跨租户全局 `User`。

`idempotency_key` 为必填字段。`Submission` 是服务端持久化提交记录，`IN_PROGRESS` / `PENDING_SYNC` 是提交生命周期状态，不代表可无幂等键。本阶段不定义无幂等键的服务端草稿记录。同一 `enrollment` 下 `idempotency_key` 必须唯一（`@@unique([enrollmentId, idempotencyKey])`），不同学校或学生可复用相同客户端 key。

`attempt_no` 表示同一 `assignment` 下该 `enrollment` 的整体提交序号，由 `@@unique([assignmentId, enrollmentId, attemptNo])` 保护，禁止客户端重复分配。

状态语义：

- `IN_PROGRESS`：服务端已建立提交记录，作答尚未完成；`submitted_at` 可为空。
- `PENDING_SYNC`：服务端已接收离线提交元数据，仍有内容待同步；`submitted_at` 可为空。
- `SUBMITTED` 及之后状态：`submitted_at` 必须有值。

## SpeechResult

- `audio_asset_id`
- `target_text_version`
- `provider`
- `provider_model`
- `quality_flags`
- `recognized_text`
- `alignment`
- `score_components`
- `confidence`
- `processing_ms`
- `review_status`

## AuditLog

- `school_id`
- `actor_user_id`
- `action`
- `resource_type`
- `resource_id`
- `before_summary`
- `after_summary`
- `request_id`
- `created_at`

不得在审计日志中记录密码、完整 token、原始敏感音频或不必要的个人明细。

## Campus

- `school_id`
- `name`
- `code`（可选）
- `timezone`（可选，默认继承 School）
- `is_active`

## AssignmentTarget

- `school_id`
- `assignment_id`
- `target_type`：`CLASS` / `STUDENT`
- `class_id`（`CLASS` 目标时非空）
- `enrollment_id`（`STUDENT` 目标时非空）

`AssignmentTarget` 是任务投放目标的唯一事实源。`Assignment` 不再保留 `class_id`。

- 班级目标：`target_type = CLASS` 且 `class_id` 指向 `Class`。
- 学生目标：`target_type = STUDENT` 且 `enrollment_id` 指向 `Enrollment`（学校内班级身份），不直接引用跨租户 `User`。
- `GROUP` 等目标类型延后实现。

数据库 CHECK 约束 `AssignmentTarget_target_check` 保证一行记录只能是一种合法目标：

- `CLASS`：`class_id` 非空且 `enrollment_id` 为空；
- `STUDENT`：`enrollment_id` 非空且 `class_id` 为空。

该约束同时拒绝：两者均空、两者均非空、`target_type` 与字段不匹配。

Prisma schema 无法原生表达该条件 CHECK，因此约束由 `migration.sql` 维护。后续重新生成迁移时必须保留此约束，否则 `infra/database/prisma/migration.contract.test.mjs` 会失败。

`Assignment` 至少需要一个 `AssignmentTarget`，由服务层校验；无目标的任务不允许发布。

## ActivityAttempt

- `school_id`
- `submission_id`
- `activity_id`
- `kind`
- `value`
- `auto_result`

唯一约束：`(submission_id, activity_id)`。`ActivityAttempt` 是学生在一次 `Submission` 中对某个 `LearningActivity` 的作答记录；`Submission.attempt_no` 表示同一任务的整体第几次提交。

MVP 中，一个活动在一次提交内只允许一个 `ActivityAttempt`。语音重试等需要多次作答的场景通过生成新的 `Submission`（新的 `attempt_no`）来表达。`AudioAsset` 绑定到 `ActivityAttempt`。

## Feedback

- `school_id`
- `submission_id`
- `author_user_id`
- `decision`
- `comment`
- `score`
- `revision`
- `released_at`

数据库允许一个 `Submission` 关联多条 `Feedback`，用于保留历史修订。API 默认返回最新一条已 `released` 的有效 `Feedback`；旧 `Feedback` 不通过普通学生 API 列出，历史记录由后续审计或管理 API 暴露。

`revision` 用于反馈并发控制，API `If-Match` 头对应 `Feedback.revision`；冲突返回 `409`。

## ContentPackage

- `school_id`
- `course_version_id`
- `device_id`（可选）
- `status`：`PENDING` / `BUILDING` / `READY` / `EXPIRED` / `FAILED`
- `manifest`
- `expires_at`

## SyncJob

- `school_id`
- `device_id`
- `client_operation_id`
- `status`：`QUEUED` / `RUNNING` / `COMPLETED` / `FAILED` / `CANCELLED`
- `started_at`
- `completed_at`
- `summary`
- `error_code`

`SyncJob` 表示一次 `sync/push` 请求。`client_operation_id` 是请求级幂等标识，用于防止同一设备重复创建同步任务。

唯一约束：

- `(school_id, device_id, client_operation_id)`：请求级幂等；
- `(school_id, device_id, id)`：作为 `SyncOperation` 复合外键的目标。

`SyncJob.client_operation_id` 对应 API `sync/push` 请求级别的标识；`SyncOperation.operation_id` 对应请求内单个操作项的标识。一个 `SyncJob` 包含多条 `SyncOperation`。

## SyncCursor

- `school_id`
- `device_id`
- `entity_type`：`ASSIGNMENT` / `SUBMISSION` / `PROGRESS` / `CONTENT_PACKAGE` / `FEEDBACK`
- `last_synced_at`
- `last_entity_id`

唯一约束：`(device_id, entity_type)`。

Cursor 语义：`last_synced_at` 与 `last_entity_id` 共同构成单调递增位置。拉取端点将这两个字段编码为不透明字符串 cursor；客户端不得解析 cursor 内容。服务端只返回比该位置更新的记录。同一设备、同一实体类型只有一条 cursor。

## SyncOperation

- `school_id`：通过复合外键与所属 `SyncJob` 保持一致
- `device_id`：通过复合外键与所属 `SyncJob` 保持一致
- `sync_job_id`：所属 `SyncJob` 的 ID
- `actor_user_id`
- `operation_id`
- `entity_type`
- `entity_id`
- `action`
- `base_revision`
- `payload_hash`
- `status`
- `result`

`SyncOperation` 必须归属且只属于一条 `SyncJob`。设备归属通过 `SyncOperation → SyncJob → Device` 获得，不再维护独立的 `Device` 直接关系。

唯一约束：`(school_id, actor_user_id, operation_id)`。同一学校、同一 actor 的 `operation_id` 不能重复；不同学校互不影响。

`entity_type` 在 schema 中为 `String`，MVP 允许的枚举由 GOV-002 API 契约限制，数据库层不做强枚举约束；服务层必须校验并拒绝未知类型。

## 公共策略

### 租户隔离

- 根租户为 `School`。
- 所有租户级表均携带 `school_id`（直接或通过父级派生）。
- `Submission`、`Feedback`、`Device`、`ContentPackage`、`SyncJob`、`SyncCursor`、`SyncOperation` 均直接持有 `school_id`，便于作用域查询与审计。
- `User` 为跨租户身份，通过 `Membership` 获得学校权限。

### 软删除

MVP 仅在以下实体保留 `deleted_at` 字段，其余组织/教学实体通过状态或生命周期字段管理：

- `School`：租户级实体，删除后保留审计与历史数据。
- `Course`：课程内容资产，删除后历史版本/引用仍可能保留。
- `Assignment`：教学任务记录，删除后已产生的提交与反馈仍保留。
- `Submission`：学生学习产出，软删除满足审计与未成年人数据保护要求。
- `Feedback`：教师评分/反馈记录，软删除满足审计要求。
- `Resource`：内容资源元数据，删除后对象存储文件按保留策略处理。
- `Device`：学校管理设备，删除后同步历史可能仍保留。

不启用软删除的实体及原因：

- `Membership`、`Enrollment`：通过 `status = LEFT` 表达离校/退班，避免唯一约束与复用冲突。
- `Term`、`Class`：通过生命周期/状态管理；名称等唯一值需要可复用。
- `Campus`、`User`：MVP 中 `Campus` 通过 `isActive` 管理；`User` 为跨租户身份，由平台生命周期管理，本次不增加 `deleted_at`。

带唯一约束且启用软删除的实体：

- `School.code`、`User.loginIdentifier`、`Course.stableKey`、`Resource.objectKey`：删除后关键标识符不复用，由业务规则保证。
- `Submission.enrollmentId + idempotencyKey`、`Submission.(assignmentId, enrollmentId, attemptNo)`：提交为历史事件，删除后键值不复用。

已发布课程版本通过 `RETIRED` 状态管理，不物理删除；子内容随版本级联保护。服务层查询必须追加 `deleted_at IS NULL` 过滤；物理删除仅用于数据保留策略，需显式授权。

### 时区与时间字段

- 所有 `DateTime` 以 UTC 存储。
- `School.timezone` 用于展示与排期转换。
- 业务时间字段：`starts_at`、`due_at`、`submitted_at`、`published_at`、`retired_at`、`released_at`、`last_seen_at`、`last_synced_at`。

### JSON 字段使用边界

JSON 字段仅用于结构化业务数据或扩展元数据，不得存储：

- 个人敏感信息（身份证、住址、监护人联系方式等）；
- 完整音频/大文件原始内容（应使用对象存储 + `Resource.object_key`）；
- 密码、token、密钥；
- 未版本化的分析事件大 payload。

典型 JSON 字段：`objectives`、`completion_rule`、`content`、`value`、`auto_result`、`result`、`quality`、`manifest`、`summary`、`before_summary`、`after_summary`。

### 级联删除限制

- `CourseVersion` 被 `Assignment` 引用时禁止删除（`ON DELETE RESTRICT`）。
- `User` 作为提交学生或反馈作者时禁止删除（`ON DELETE RESTRICT`）。
- `Resource` 被活动或音频引用时禁止删除（`ON DELETE RESTRICT`）。
- `LearningActivity` 被 `ActivityAttempt` 引用时禁止删除（`ON DELETE RESTRICT`）。
- 复合外键子表 `schoolId` 为必填时不得使用 `SET NULL`，否则 PostgreSQL 会将整组外键列置空。以下可选关联关系使用 `ON DELETE RESTRICT`，由服务层在删除父表前解绑或拒绝：
  - `Class.campus` → `Campus`
  - `Device.campus` → `Campus`
  - `Device.owner` → `Membership`
  - `ContentPackage.device` → `Device`
  - `Submission.device` → `Device`
- 学校/班级删除会级联删除其下教学数据，但保留审计日志（`SET NULL`）。

### 租户复合约束

以下关键关系通过复合唯一键 `@@unique([schoolId, id])` 与复合外键在数据库层保证 `child.school_id == parent.school_id`：

- `Class.(schoolId, termId)` → `Term.(schoolId, id)`
- `Enrollment.(schoolId, classId)` → `Class.(schoolId, id)`
- `CourseVersion.(schoolId, courseId)` → `Course.(schoolId, id)`
- `Assignment.(schoolId, courseVersionId)` → `CourseVersion.(schoolId, id)`
- `AssignmentTarget.(schoolId, assignmentId)` → `Assignment.(schoolId, id)`
- `AssignmentTarget.(schoolId, classId)` → `Class.(schoolId, id)`
- `AssignmentTarget.(schoolId, enrollmentId)` → `Enrollment.(schoolId, id)`
- `Submission.(schoolId, assignmentId)` → `Assignment.(schoolId, id)`
- `Submission.(schoolId, enrollmentId)` → `Enrollment.(schoolId, id)`
- `Submission.(schoolId, deviceId)` → `Device.(schoolId, id)`
- `ActivityAttempt.(schoolId, submissionId)` → `Submission.(schoolId, id)`
- `ActivityProgress.(schoolId, enrollmentId)` → `Enrollment.(schoolId, id)`
- `ContentPackage.(schoolId, courseVersionId)` → `CourseVersion.(schoolId, id)`
- `ContentPackage.(schoolId, deviceId)` → `Device.(schoolId, id)`
- `Feedback.(schoolId, submissionId)` → `Submission.(schoolId, id)`
- `SyncJob.(schoolId, deviceId)` → `Device.(schoolId, id)`
- `SyncCursor.(schoolId, deviceId)` → `Device.(schoolId, id)`
- `SyncOperation.(schoolId, deviceId, syncJobId)` → `SyncJob.(schoolId, deviceId, id)`
- `Device.(schoolId, campusId)` → `Campus.(schoolId, id)`
- `Device.(schoolId, membershipId)` → `Membership.(schoolId, id)`

不能仅由数据库强制、需服务层补充的边界：

- `Assignment` 至少需要一个 `AssignmentTarget`；无目标的任务不允许发布。
- `Submission.idempotencyKey` 为空时仅表示草稿/中间状态，最终提交应由客户端提供唯一键；重复提交由服务层返回相同结果。
- `SyncOperation` 的幂等边界为 `(schoolId, actorUserId, operationId)`，由数据库唯一约束保证；服务层仍需校验写入用户属于该学校。
