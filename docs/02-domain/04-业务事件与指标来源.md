# 业务事件与指标来源

事件不是用来堆“大数据”概念，而是支持可靠报表、审计和产品改进。

## 事件命名

`<bounded_context>.<aggregate>.<past_tense>`

示例：

- `curriculum.course_version.published`
- `teaching.assignment.opened`
- `learning.activity.started`
- `learning.activity.completed`
- `learning.submission.submitted`
- `offline.sync.conflict_detected`
- `speech.job.finalized`
- `assessment.feedback.released`

## 公共字段

- `event_id`
- `event_name`
- `event_version`
- `occurred_at`
- `actor_id`
- `school_id`
- `aggregate_type`
- `aggregate_id`
- `request_id`
- `source`
- `payload`

## 规则

- 事件 payload 只包含生成指标所需的最小字段；
- 不把完整学生档案、音频、答案全文塞进分析事件；
- 事件 schema 有版本；
- 关键业务写入和 outbox 事件在同一数据库事务中完成；
- 报表必须注明使用哪些事件和筛选条件；
- 删除/更正数据时要考虑派生报表如何更新。
