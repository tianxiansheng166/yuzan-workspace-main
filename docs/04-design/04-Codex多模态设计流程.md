# Codex 多模态前端设计流程

Codex 负责实现和视觉迭代，但必须受产品状态、契约和设计审查约束。

## 每个页面的工作顺序

### 1. 读取上下文

Codex 必须先读：

- `docs/01-product/` 对应旅程；
- `docs/04-design/`；
- OpenAPI 和当前 mock；
- task 文件的 allowed paths 和完成定义。

### 2. 视觉研究

收集少量高质量对标截图，只分析：

- 信息优先级；
- 网格与留白；
- 字体比例；
- 图片裁切；
- 状态反馈；
- 移动端重新构图。

不能照搬视觉资产、商标和受版权保护的具体画面。

### 3. 提出三个结构方案

方案差异必须是构图和交互差异，而不是换颜色。产品负责人选定一个后才实现。

### 4. 先覆盖状态矩阵

页面至少设计：

- normal
- loading
- empty
- error
- offline
- pending sync
- permission denied
- long content
- low-confidence AI result（相关页面）

### 5. 构建真实垂直切片

优先使用 OpenAPI mock，随后接真实 API。禁止硬编码“完成率 92%”等业务数据。

### 6. 浏览器视觉 QA

至少截取：

- 1440×900
- 1024×768
- 390×844

检查：

- 卡片套卡片；
- 文本溢出；
- 键盘焦点；
- 触控区域；
- 背景可读性；
- 网络/同步状态；
- 藏文字符；
- reduced motion；
- 控制台错误。

### 7. 生成资产

当页面需要原创封面、纹理或图标概念时，使用 `design-lab/asset-briefs/`。生成后：

- 登记 prompt、模型、日期、用途和人工修改；
- 不在图片中烘焙重要文字；
- 图标概念必须人工重绘为简洁 SVG；
- 导出 AVIF/WebP/PNG 与响应式尺寸；
- 增加 alt/装饰性标记；
- 检查文化准确性和版权。

## Codex 完成报告必须包含

- 修改文件；
- 实现的用户任务；
- API/mock 依赖；
- 所有状态截图；
- 可访问性检查；
- 性能和资源体积；
- 未解决的视觉风险；
- 不得用“更高级”“更有设计感”替代具体证据。
