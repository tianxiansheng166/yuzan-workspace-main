# 设计系统规范

## Token 层级

1. Primitive：原始色值、字号、空间、半径、时长。
2. Semantic：背景、正文、强调、危险、成功、焦点。
3. Component：按钮、输入、导航、提示等局部 token。
4. Feature：业务页面内部组合，不进入通用 UI 包。

禁止业务代码直接使用任意 hex、阴影和 z-index。

## 字体

- 中文正文优先系统可用、清晰、授权可靠的字体栈；
- 藏文需要单独做字符覆盖、行高和断行测试；
- 品牌大标题可使用有授权的展示字体，但不能牺牲加载和可读性；
- 正文建议 16px 起，学生端触控区域至少 44×44 CSS px；
- 长文本保持合理行宽。

## 颜色

基准：

- 米白：主内容底；
- 酒红：品牌与主要动作；
- 浅绿：进度、恢复和自然背景；
- 暖金/橙：有限强调；
- 墨黑/深灰：高对比正文。

所有语义颜色必须通过对比度检查；不能仅靠颜色表达状态。

## 圆角与阴影

- 圆角是材料语言，不是默认；
- 页面大容器通常不需要完整边框；
- 同一视图最多 2–3 个圆角层级；
- 阴影只用于浮层、拖动和真实空间层级；
- 用分隔、背景和留白代替卡片堆叠。

## 动效

动效服务：

- 状态变化；
- 空间关系；
- 保存/同步反馈；
- 录音和播放；
- 任务路径推进。

支持 `prefers-reduced-motion`，避免持续大面积背景动画。关键操作动画不超过理解所需时间。
