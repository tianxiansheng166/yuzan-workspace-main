## 版本目标

本版本结束时必须能证明三件事：

- 学生可以收到一份属于自己的真实任务，完成录音与理解题，并得到来源可追溯的反馈；
- 教师可以看到真实班级进度和动态提交，完成复核、要求重做或投递巩固；
- 学校可以确定谁在什么组织中访问了哪些学生数据，并进行最小账号与授权管理。

## 用户与权限

| 角色 | 可读 | 可写 | 明确禁止 |
| --- | --- | --- | --- |
| 学生 | 自己的任务、尝试、录音状态、报告、巩固 | 自己的答案、录音、提交、复测 | 访问他人提交；修改机器/教师结果；进入管理端 |
| 教师 | 所属班级的任务、进度、提交、证据、报告 | 投递、复核、反馈、重做和巩固 | 访问无班级关系的学生；覆盖原始提交 |
| 学校管理员 | 本校组织、账号、班级、授权、汇总和审计 | 邀请/停用账号、班级关系和授权 | 查看无必要的学生音频内容；跨校操作 |
| 内容管理员 | 已授权内容和版本 | 创建草稿、审核、发布或下架内容版本 | 修改已经产生提交的历史版本 |

权限判断必须在服务端执行。隐藏按钮不是权限控制；任何越权读取和修改都应返回明确错误并留下必要审计信息。

## 业务闭环

### 正常主线

| 步骤 | 责任角色 | 输入 | 系统行为 | 产出 |
| --- | --- | --- | --- | --- |
| 1. 创建投递 | 教师 | 班级、练习版本、截止时间 | 校验教师班级权限，保存草稿 | `Delivery:DRAFT` |
| 2. 发布任务 | 教师 | 已确认投递 | 生成对目标学生可见的任务 | `Delivery:OPEN` |
| 3. 开始练习 | 学生 | 可访问任务 | 创建唯一 Attempt，绑定版本快照 | `Attempt:IN_PROGRESS` |
| 4. 保存证据 | 学生 | 文字答案、音频 | 幂等保存答案；音频直传/代理上传并登记 Recording | Answer + `Recording:*` |
| 5. 提交 | 学生 | 完整性确认 | 锁定本 revision，创建处理任务 | `Attempt:SUBMITTED` |
| 6. 自动处理 | 系统 | 提交与音频 | 调度语音/规则处理，保存原始供应商结果 | `ProcessingJob:*` |
| 7. 分流 | 系统 | 结果与规则 | 高置信度进入可报告；低置信度/异常进入复核 | `Review:PENDING` 或可生成报告 |
| 8. 教师复核 | 教师 | 录音、答案、机器证据 | 锁定任务，确认/修改/要求重做 | `Review:CONFIRMED/REDO_REQUIRED` |
| 9. 生成报告 | 系统 | 已确认结果 | 创建不可覆盖的报告 revision | `Report:PUBLISHED` |
| 10. 投递巩固 | 教师/规则 | 报告薄弱点 | 创建带来源关系的巩固任务 | `Intervention:ASSIGNED` |
| 11. 学生复测 | 学生 | 巩固任务 | 新建 Attempt，不覆盖原记录 | 新 Attempt + 进步对比 |

### 关键异常

- 音频权限拒绝：解释用途，允许重新授权或改做非录音题；不得伪造录音成功；
- 弱网/上传中断：保留本地待上传状态，重试不得生成重复 Recording；
- 重复点击提交：同一幂等键只产生一个有效提交；
- 供应商超时：进入可见的“处理中/处理失败/待人工复核”，不得返回虚构分数；
- 教师并发复核：旧 revision 提交返回冲突，由前端提示刷新；
- 截止后提交：是否允许迟交由投递规则决定并明确标记；
- 学生被移出班级：历史证据保留策略由授权与数据政策决定，不能直接静默删除；
- 报告生成失败：保留已确认复核结果，可重试生成，不能要求教师再次评分。

## 页面级关键规则

### S05 练习执行器

- 进入时锁定 `PracticeVersion`，练习发布后内容更新不影响当前 Attempt；
- 每个答案保存使用 Attempt、Item 与 revision 组成幂等边界；
- 音频必须能回放确认；上传成功以服务端 Recording 状态为准；
- 离开页面前提示未同步内容；刷新或重新进入可以恢复已保存进度；
- 不显示未经教师/规则确认的确定性结论。

### T04—T06 教师复核

- 默认优先级：即将逾期的低置信度提交 → 处理异常 → 普通抽检；
- 列表至少显示学生、班级、练习、提交时间、触发原因、处理状态；
- 领取/打开复核任务时建立短期锁或 revision；
- 修改机器结果必须填写理由，机器原结果不可覆盖；
- 要求重做必须填写学生可理解的说明；
- 上一条/下一条切换不得丢失未保存修改；
- 无权限教师不能通过猜测 ID 访问音频或结果。

### S07 报告

- 报告必须标明“自动处理”“教师已复核”或“等待复核”的来源状态；
- 不可用或待复核时显示下一步和预计处理责任，不显示假分数；
- 报告 revision 与产生它的 Attempt、Review 和内容版本可追溯；
- 教师要求重做后，原报告与原 Attempt 保持只读，新任务另行生成。

## 数据与接口要求

- 所有业务接口从登录态解析用户、学校和角色，不从前端固定常量信任身份；
- 列表接口必须支持权限过滤、分页、稳定排序和空状态；
- 创建 Attempt、提交、上传登记、复核提交和报告生成均需要幂等机制；
- 更新操作携带 revision；冲突统一返回 409 或契约定义的等价错误；
- 音频使用受控对象存储，访问使用短时授权地址，不公开桶；
- 异步任务保存状态、重试次数、供应商请求标识、失败原因和时间戳；
- API 错误码应区分无权限、资源不存在、状态不允许、冲突、供应商失败和系统失败；
- OpenAPI、生成类型、服务端实现和前端调用必须在同一契约变更中保持一致。

## 埋点与指标口径

仅采集支持产品验证的最小事件：任务发布、任务到达、开始练习、答案保存、录音上传成功/失败、提交、处理完成/失败、复核开始/完成、报告查看、重做开始/完成。

每个指标必须记录分母、时间窗和去重方式。例如“有效提交率”应定义为：在统计周期内，至少产生一个满足必答项并完成服务端提交的学生数 ÷ 实际收到 OPEN 投递的学生数。不得用页面访问量代替完成率。

## 验收标准

### 功能验收

- Given 教师属于目标班级，When 发布有效练习，Then 新登录的目标学生能看到动态任务；
- Given 学生不属于目标班级，When 猜测任务 ID，Then 服务端拒绝读取；
- Given 学生完成录音与必答题，When 重复点击提交，Then 只产生一个有效提交；
- Given 录音上传中断，When 使用同一幂等信息重试，Then 不产生重复有效 Recording；
- Given 提交触发低置信度，When 处理完成，Then 动态提交进入教师复核队列；
- Given 教师无该班级权限，When 猜测提交 ID，Then 不可读取录音与答案；
- Given 教师修改机器结果，When 提交，Then 必须保存理由、机器原值、教师值、reviewer 和 revision；
- Given 两位教师同时修改，When 后提交旧 revision，Then 返回冲突且不覆盖新结果；
- Given 教师要求重做，When 学生重新提交，Then 生成新 Attempt，原 Attempt 保持只读；
- Given 供应商不可用，When 学生查看报告，Then 显示真实不可用/待复核状态，不返回伪造分数；
- Given 报告已发布，When 学生完成巩固复测，Then 可追溯原 Attempt、Intervention 和新 Attempt。

### 体验验收

- 390px 宽度下核心内容无重叠、裁切和横向滚动；
- 关键按钮触控区域、录音状态和提交反馈清晰；
- 弱网、无权限、空数据、失败和重试均有可操作反馈；
- 教师可只用键盘完成核心筛选和复核操作；
- 学生报告不依赖颜色单独表达结论。

## 完成定义

一个功能只有同时满足以下条件才可标记完成：

1. 源码、契约、数据库迁移和权限规则一致；
2. 自动化测试覆盖正常路径、越权、冲突和至少一个失败路径；
3. 使用真实 API、真实登录态和动态 ID 完成浏览器流程；
4. 数据库或日志能证明对象和状态按设计流转；
5. 页面在目标手机宽度和教师桌面宽度通过视觉检查；
6. 重启环境后流程可重复；
7. 证据记录版本 SHA、命令、账号角色、对象 ID、截图和已知限制；
8. 不存在假 token、固定业务 ID、固定业务结果或 API 失败静默兜底。

## 上线门禁

- 比赛门禁：稳定三轮演示、离线备份材料、现场网络降级方案；
- 功能门禁：唯一 P0 全链路 `FLOW_VERIFIED`；
- 数据门禁：真实数据来源、保留和删除规则获批准；
- 合规门禁：未成年人授权、隐私文本、录音用途和供应商数据路径确认；
- 教研门禁：首个内容版本、评分规则和人工复核边界确认；
- 实施门禁：学校、设备、账号、培训、支持和故障联系人确认；
- 运维门禁：监控、备份、恢复、密钥轮换和事故响应最小能力存在。

任何一项未满足时，只能声明相应层级的“原型/演示/待验证”，不能统一称为“已上线”。
