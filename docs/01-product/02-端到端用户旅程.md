# 端到端用户旅程

## 旅程 A：教研发布课程

1. 教研创建课程草稿，填写年级、学期、学习目标和适用方言。
2. 添加单元、课时和有序活动。
3. 上传或选择已审核资源。
4. 为活动配置完成条件和评价规则。
5. 运行内容校验：缺失资源、版权、翻译、时长、离线可用性。
6. 提交审核。
7. 审核者提出修改或批准。
8. 发布生成不可变 `CourseVersion`。
9. 后续修改必须从版本派生新草稿。

异常：

- 资源上传失败；
- 版权状态未知；
- 课程存在未翻译必填文本；
- 已发布版本被任务引用，不允许原地修改。

## 旅程 B：教师布置任务

1. 教师进入“教学工作台”，系统优先展示待处理事项。
2. 选择班级和已发布课程版本。
3. 选择课时/活动、截止时间、完成标准和离线要求。
4. 系统预检：目标学生、资源体积、设备/网络适配。
5. 发布任务并记录快照。
6. 学生收到站内通知；离线设备在下次同步时获得任务。

异常：

- 教师不属于班级；
- 课程已下架但已有版本仍允许查看；
- 学生设备空间不足；
- 发布后变更需要生成 revision 并保留历史。

## 旅程 C：学生完成今日任务

1. 登录后首页只突出今日任务和继续学习。
2. 系统说明网络状态、下载状态和预计大小。
3. 学生完成活动，进度自动保存。
4. 客观题即时保存；语音先本地质检再进入处理队列。
5. 学生提交，获得本地回执与服务器确认状态。
6. 断网时提交进入 outbox，页面明确显示“等待同步”。
7. 联网后后台同步并处理冲突。
8. 学生收到教师反馈和下一步。

## 旅程 D：教师复核与干预

1. 教师看到按风险排序的队列：未完成、低置信度、反复错误、同步失败。
2. 打开提交时同时看到原始答案/录音、自动结果、置信度和历史。
3. 教师确认、修正、批注、退回或标记需线下辅导。
4. 系统记录自动结果与教师最终结果的差异，用于评测而非偷偷训练。
5. 学生收到可理解、可行动的反馈。

## 旅程 E：学校运营

1. 查看活跃班级、任务完成、内容下载、同步失败和设备异常。
2. 指标可以下钻到班级，但默认不显示不必要的学生敏感信息。
3. 导出报表有时间范围、口径版本和生成记录。
4. 管理员可查看审计日志和数据导出记录。
