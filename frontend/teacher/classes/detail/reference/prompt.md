【页面存在的原因】
把班级整体学习状态、学生差异和教学行动放在同一张可下钻的学情地图中，帮助教师决定下一节课和下一次干预。

【空间构图与视觉重心】
页面采用“横向班级成长河谷”。上方是班级信息、当前课程与本周教学目标；中央 60% 是连续路径地图，学生以小型节点分布在课程、练习、测评、复测阶段，不以排行榜羞辱学生。左下是发音问题聚类区，用声纹和音节标签呈现；右下是教师行动台，提供补课、复测、分组任务和联系志愿者。右侧窄栏显示时间范围、筛选和班级报告导出。

【必须出现的业务元素】
1. 班级概况与当前课程
2. 学生学习阶段分布
3. 高频发音问题与书面问题
4. 任务完成和复测进度
5. 需关注学生但不公开排名
6. 发起分组任务、批量复测、查看报告
7. 数据时间范围和同步状态

【关键交互与机器反馈】
选择某个问题聚类时，对应学生节点和课程节点通过路径线关联；选择学生后打开侧边档案而不是跳出弹窗墙。

【状态表达】
这张主图应以最典型的正常工作状态为主，同时在局部以可识别但不喧宾夺主的方式预留以下状态语言：

【艺术方向】
- 视觉中心必须是当前业务的核心路径或核心工作对象，不是统计数字。
- 使用高原红承担主行动和公益连接；青稞绿承担完成和成长；深夜藏蓝承担技术与稳定；雪山灰白承载阅读；路径金只做连接高光。
- 背景需要有层次：近景为可工作的 UI 画布，中景为地形线/声场/路径，远景为极克制的山脊或纸张纹理。
- 插画只在能解释业务关系时出现，不得占据主要操作区。
- 设计应有成熟教育产品的精密秩序，也保留援藏公益项目的人情温度。

【前端实现边界】
真实学生节点、问题标签、统计数字和操作由前端生成；地形底图和路径纹理可作为装饰资产。
- 真实姓名、学校、班级、数量、成绩、报告、权限、登录状态、链接、二维码、表单值、AI 结果和同步状态必须由真实数据与前端代码渲染。
- 按钮、输入框、导航、表格、筛选、弹层、可访问状态必须用 Vue/HTML/CSS 重建，不能从图片裁切。
- 参考图中的任何假数据均不得进入生产。
- 不得因为视觉图改变既有 API、权限、租户隔离、离线语义或真实状态机。

【响应式收束】
- 1440px：完整呈现主要构图和辅助侧栏。
- 768px：主工作流优先，次要侧栏折叠为抽屉或分段区。
- 390px：只保留一个主要行动与明确下一步，复杂地图转为纵向路径；不得简单缩小三栏布局。
- 所有触控目标、焦点和文本必须可访问；支持 `prefers-reduced-motion`。
