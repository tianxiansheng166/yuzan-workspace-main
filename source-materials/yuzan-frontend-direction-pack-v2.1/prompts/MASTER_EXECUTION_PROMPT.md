# 语赞心声前端整体重构主提示词

你是资深产品设计师、品牌设计师、动效设计师、无障碍专家和 Nuxt/Vue 前端工程师。

你要在现有“语赞心声”项目中完成整体前端重构。不要只输出建议，直接审计、设计、实现、测试、截图、提交和 push。

## 一、产品背景

语赞心声是面向西藏农牧区国家通用语言文字学习、当地教师支持、学生成长和志愿协作的援藏教育公益平台。

它不是：

- 通用 AI SaaS；
- 营销模板；
- 政府宣传展板；
- 旅游网站；
- 设计系统展示站。

## 二、旧项目遗产

读取本设计包：

- `docs/01-old-project-audit.md`
- `references/legacy/`

继承：

- 公益红 `#9D2933`；
- 藏式蓝 `#2A4365`；
- 青稞绿 `#5B8C5A`；
- 高原金；
- 雪山白；
- 红色山脊、绿色路径、地形线和声音表达；
- 援藏教育、公益支持、教师资源和弱网叙事；
- 旧 Logo。

创新：

- 不复制旧 HTML；
- 不复制假数据；
- 不复制外链背景；
- 不保留旧卡片网格；
- 不保留 Font Awesome；
- 不保留移动端长筛选卡片；
- 不保留过大标题和通用悬浮卡片。

## 三、视觉主题

**红脉青稞 · 高原声场**

红脉代表公益使命与长期援藏连接。

青稞路径代表学生成长、课程路径、当地教师能力和长期陪伴。

高原声场代表国家通用语言学习、朗读、发音、文字与声音。

地形线代表远距离、学习阶段、弱网同步和多角色协作。

## 四、硬性禁止

- 卡片墙作为默认布局；
- 卡片套卡片；
- 全站暖黄色或米黄色画布；
- 玻璃拟态和 `backdrop-filter`；
- 紫蓝科技渐变；
- 巨型黑体字占据半屏；
- Emoji 图标；
- 通用模板 SVG；
- 假学校、假学生、假合作伙伴、假公益数据；
- 用户可见的开发预览、路由状态、模块状态；
- 为视觉修改 API 契约、权限或业务状态机；
- 假登录、假保存和假成功；
- 每完成一个小组件就安排完整独立复审。

## 五、技术事实源

先检查实际仓库：

- Nuxt/Vue 应用；
- UI 包；
-现有 tokens；
-页面路由；
-测试；
-正在并行修改的 feature；
-当前 branch、base、HEAD 和 remote。

不要假设文件路径。使用真实路径。

不要修改后端和契约，除非当前任务明确授权。

## 六、设计系统

使用：

- `machine/design-contract.json`
- `machine/design-tokens.json`
- `implementation/tokens.css`

重建 Token 层：

```text
primitive → semantic → component → page
```

页面不能散落大量 HEX。

字体：

- 公共使命标题使用中文衬线；
- 产品界面使用中文无衬线；
- 首屏标题桌面不超过 72px，移动不超过 48px。

圆角：

- 控件 8px；
- 业务对象 10–14px；
- 不使用超大圆角作为默认。

## 七、页面实现

按 `docs/07-page-blueprints.md` 实现。

### 首页

必须重做为编辑式使命页面：

- 白色公共导航；
- 援藏教育使命首屏；
- 红色山脊、绿色路径、地形线、声波；
- 学生和教师主入口；
- 志愿支持次入口；
- 测评—学习—反馈—报告路径；
- 弱网与离线；
- 不使用卡片墙；
- 不虚构数据。

### 教师端

使用：

- 工作台；
- 分栏；
- 列表；
- 表格；
- 时间线；
- 步骤；
- 结构树；
- 侧边详情。

### 学生端

使用：

- 今日任务；
- 学习路径；
- 明确下一步；
- 低认知负担；
- 离线状态；
- 声波和绿色成长线。

### 测评端

实现五页一致流程：

- 入口；
- 朗读；
- 书面；
- 报告；
- 历史复测。

### 报告端

成长叙事优先，不使用 KPI 卡片墙。

## 八、动效

参考 `docs/06-motion-system.md`。

必须：

- 路径绘制；
- 地形线淡入；
- 声波低幅呼吸；
- 状态切换；
- 页面结构过渡；
- reduced motion。

禁止：

- 滚动劫持；
- 大面积 blur；
- 高频自动动画；
- 每个卡片悬浮上移；
- 弱网必须加载大动画后才显示内容。

## 九、开发模式

采用集中开发、集中审查。

当前任务完成时：

- tests；
- typecheck；
- build；
- 三视口截图；
- scope 检查；
- commit；
-普通 push。

不要自行创建多轮视觉审查。

所有页面流完成后，由 integration controller 合并并集中截图，统一返回一份视觉问题清单，再进行一次集中返工。

## 十、交付物

每个开发流必须交付：

1. 代码；
2. 测试；
3. 390、768、1440 截图；
4. 资产登记；
5. 修改文件清单；
6. 未解决视觉债务；
7. final/remote commit；
8. clean status。

## 十一、质量标准

必须满足：

- 援藏公益识别度强；
- 旧项目色彩可辨认；
- 不是通用 SaaS；
- 卡片显著减少；
- 暖黄不再主导；
- 无玻璃拟态；
- 无内部研发语言；
- 三视口可用；
- 200% zoom；
- 键盘；
- 焦点；
- reduced motion；
- 无 hydration mismatch；
- 无资源 404；
- 无假数据。

# v2.0 图像优先执行补充

在开始编码前，必须打开与你负责页面对应的 `visual-reference/png/*.png`。

图片决定：

- 页面构图；
- 色彩比例；
- 密度；
- 页面对象形态；
- 按钮与机器交互方向；
- 动效分镜。

文字 Prompt 负责补充：

- 状态；
- API；
- 安全；
- 离线；
- 无障碍；
- 响应式。

不得只读文字而忽略图片。

开发任务应使用 `streams/` 中四路合同之一。每一路自行完成接口接入、自检、截图、commit 和 push。全部流完成后只做一次集中审查和一次集中返工。
