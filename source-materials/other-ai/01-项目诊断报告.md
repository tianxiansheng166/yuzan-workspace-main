---

## 一、总体判断

**当前状态：可运行的演示原型（Demo），不是可交付的产品。**

项目已搭建起基本的前后端骨架，但距离"能投入正常使用"的产品仍有根本性差距。核心问题不是"功能不够多"，而是**底层架构无法支撑生产环境运行**。

---

## 二、逐层诊断

### 2.1 数据层 —— 根本性的致命缺陷

| 问题 | 现状 | 生产级要求 |
|------|------|-----------|
| 存储方式 | JSON文件读写（`fs.readFileSync/writeFileSync`） | 关系型数据库（PostgreSQL）+ 缓存（Redis） |
| 并发安全 | 无。同时写入会丢数据/覆盖 | 数据库事务 + 行锁 + 乐观锁 |
| 数据一致性 | 无保障，断电/崩溃即丢数据 | WAL日志 + 定期备份 + 主从复制 |
| 查询能力 | 全量加载到内存再过滤 | SQL索引查询，毫秒级响应 |
| 数据量上限 | ~1000条记录后明显卡顿 | 百万级无压力 |

**结论：JSON文件存储是最大的架构硬伤，必须优先迁移到数据库。**

### 2.2 后端层 —— 能跑但不稳健

**已实现的功能：**
- JWT认证 + bcrypt密码（已完成，但JWT_SECRET硬编码为默认值）
- 角色权限中间件（admin/teacher/student/volunteer）
- 课程CRUD API
- 用户注册/登录/资料更新
- 学习进度记录
- 公益申请提交
- AI标注/分析/语义搜索（调DeepSeek API）
- 学习行为埋点
- 文件上传（multer）

**关键缺陷：**
- `JWT_SECRET` 硬编码为 `'yuzan-xinsheng-dev-secret-2026'`，任何看过源码的人都能伪造Token
- `CORS` 完全开放（`app.use(cors())`），无域名白名单
- 输入净化仅做简单HTML标签去除，不防SQL注入（未来迁移数据库后有风险）
- 文件上传50MB限制无文件内容校验（可上传恶意文件）
- 无请求体大小限制（`express.json()` 无 limit 配置）
- 行为日志用内存数组 + 定时写入，崩溃即丢
- 所有API无速率限制（仅登录/注册有限流）
- 无日志系统（仅 console.log）

### 2.3 前端层 —— 最薄弱的环节

| 维度 | 现状 | 问题描述 |
|------|------|---------|
| 技术栈 | 原生HTML + CSS + JS | 无组件化、无状态管理、无路由、无法维护 |
| 页面结构 | 10+个独立HTML文件 | 每个页面重复导航、重复样式、重复逻辑 |
| 状态管理 | sessionStorage | 无持久化、无安全校验、刷新即丢失 |
| 响应式 | CSS媒体查询 | 基本可用但不够精细 |
| 藏语支持 | JS加载JSON翻译文件 | 仅UI翻译，内容翻译依赖静态JSON |
| 交互体验 | 基础跳转 | 无动画过渡、无骨架屏、无离线缓存 |

**核心问题：** 10+个HTML文件各自为政，任何公共修改需要逐文件同步。这是学生项目最典型的特征——只求"看起来有"，不考虑"怎么维护"。

### 2.4 微服务层 —— 纸上谈兵

```
microservices/
├── gateway/server.js      → 基础路由转发
├── services/
│   ├── user-service/       → 注册/登录骨架
│   └── course-service/     → 课程查询骨架
└── docker-compose.yml     → 容器编排配置
```

实际状况：
- 微服务代码是空壳，无业务逻辑
- Docker Compose 配置存在但从未实际运行
- 主服务 `server.js` 是单体架构，与微服务完全脱节
- 无服务发现、无健康检查、无熔断限流

**结论：微服务架构是摆设，应先做扎实单体再考虑拆分。**

### 2.5 安全层 —— 多处漏洞

| 漏洞 | 严重性 | 说明 |
|------|--------|------|
| JWT密钥硬编码 | 🔴高 | 源码公开即泄露 |
| CORS全开放 | 🔴高 | 任意域名可调用API |
| 无文件内容校验 | 🟡中 | 可上传恶意文件 |
| 行为日志内存存储 | 🟡中 | 崩溃丢失审计数据 |
| 无HTTPS强制 | 🟡中 | 生产环境必须HTTPS |
| 无CSRF防护 | 🟡中 | 跨站请求伪造风险 |

## 三、与生产级产品的差距对照

| 维度 | 当前项目 | 生产级平台 |
|------|---------|-----------|
| 数据存储 | JSON文件 | PostgreSQL + Redis |
| 并发能力 | 单进程，10人同时在线可能卡 | 万人并发，水平扩展 |

| 藏语能力 | UI翻译 | 全链路藏语（语音/文字/内容） |
| 监控运维 | 无 | Prometheus + Grafana + 告警 |
| CI/CD | 手动部署 | GitHub Actions + Docker |

## 五、核心结论

1. **JSON文件存储必须换掉**——这是从Demo到产品的分水岭
2. **前端必须组件化**——10个HTML文件无法迭代维护
3. **安全漏洞必须堵**——JWT硬编码、CORS全开放是致命伤
4. **微服务先放下**——先把单体做扎实，别搞花架子
5. **藏语能力是核心竞争力**——不能只做UI翻译，要深入到语音评测和内容翻译
6. **弱网适配是刚需**——青藏高原30%学校网络薄弱
